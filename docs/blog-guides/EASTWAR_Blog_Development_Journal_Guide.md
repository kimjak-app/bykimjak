# EASTWAR 블로그 개발일지 작업 기준

> 용도: byKimjak 블로그의 EASTWAR(삼국워) 개발일지를 채코치와 함께 작성할 때 사용하는 고정 작업 기준  
> 사용법: 새 채팅에서 이 파일을 업로드한 뒤 **“이 기준으로 오늘 블로그 작업 이어가자.”**라고 말하고, 작업 메모와 이미지를 순서대로 올린다.

---

## 1. 기본 작업 흐름

1. 김작이 오늘 또는 최근에 진행한 삼국워 작업 내용을 한글 메모 형태로 올린다.
2. 블로그 개발일지에 사용할 이미지들도 함께 업로드한다.
3. 채코치는 김작이 제공한 작업 내용과 이미지들을 확인한다.
4. 김작이 **“자료 다 올렸어. 작업해.”**라고 말하기 전에는 최종 글 작성을 시작하지 않는다.
5. 자료가 모두 올라오면 기존 byKimjak 삼국워 개발일지에 어울리는 형태로 글을 재구성한다.
6. 최종 결과에는 본문, 이미지 파일명, 이미지 삽입 위치, 필요 시 영문판, 블로그 반영용 작업지시문까지 포함한다.

---

## 2. 개발일지 작성 기준

단순한 작업 요약이 아니라 다음 흐름이 자연스럽게 드러나는 **1인 게임 개발기** 형태로 작성한다.

- 왜 이 작업을 시작했는가
- 기존에는 무엇이 문제였는가
- 어떤 고민과 시행착오가 있었는가
- 무엇을 어떻게 수정했는가
- 실제 적용 과정에서 어떤 문제가 생겼는가
- 어떻게 해결했는가
- 수정 결과가 이전보다 어떻게 좋아졌는가
- 이번 작업에서 얻은 교훈은 무엇인가
- 다음 작업은 어디로 이어지는가

기존 개발일지와 연결되는 작업이라면 이전 작업에서 무엇이 이어졌는지도 자연스럽게 설명한다.

---

## 3. 글의 톤

개발자 기술문서처럼 딱딱하게 쓰지 않는다.

EASTWAR 개발일지는 **비개발자인 시나리오 작가가 AI와 협업하며 실제 PC 전략게임을 만들어가는 과정**이 중심이다.

따라서 다음 요소를 살린다.

- 실제 작업 과정
- 고민과 선택
- 실패와 수정
- 예상 밖의 문제
- 직접 해결한 과정
- 완성 후의 성취감
- 다음 단계에 대한 판단

다만 지나치게 감상적으로 흐르지 않는다.

**실제 작업 내용과 변화가 중심이고, 감정과 생각은 그 과정을 살아 있게 만드는 정도로 사용한다.**

---

## 4. EASTWAR의 AI 협업 방식 표현

AI가 모든 것을 자동으로 만들었다는 식으로 작성하지 않는다.

EASTWAR의 실제 제작 방식은 다음 흐름으로 표현한다.

**기획 → AI 제작·코딩 → 김작의 직접 판단·수정·가공 → Godot 통합 → 실제 실행 → 오류 확인 → 수정·검증**

특히 다음 작업은 김작의 직접 제작 과정으로 분명하게 살린다.

- Photoshop 이미지 수정·합성
- 이미지 크기와 비율 조정
- UI 디자인 판단
- 생성 이미지의 일관성 보정
- 영상 편집
- 게임 화면 구성
- Godot 적용 후 실제 실행 검수
- 반복 수정
- 최종 디자인 선택

AI는 제작을 돕는 도구이며, **최종 방향 결정과 품질 판단은 김작이 담당한다는 구조**가 자연스럽게 드러나야 한다.

---

## 5. 이미지 작업 기준

김작이 올린 이미지들을 확인한 뒤 각 이미지에 사용할 **영문 파일명**을 정한다.

예시:

`eastwar_worldmap_topmenu_01.webp`

`eastwar_worldmap_city_panel_02.webp`

`eastwar_imjin_battle_cutscene_01.webp`

파일명은 다음 원칙을 따른다.

- 영문 소문자
- 단어는 `_` 또는 `-` 중 기존 블로그 규칙에 맞춰 통일
- EASTWAR 관련 파일임을 식별 가능하게 작성
- 이미지 내용이 파일명만 봐도 어느 정도 추측 가능하도록 작성
- 같은 작업의 연속 이미지는 번호 사용

---

## 6. 이미지 배치 기준

이미지를 단순히 업로드 순서대로 배치하지 않는다.

글의 흐름이 가장 잘 보이도록 채코치가 판단한다.

가능하면 다음 구조를 활용한다.

**Before → 고민/과정 → 수정 → 적용 → After**

본문에는 이미지가 들어갈 위치를 정확히 표시한다.

예:

`[IMAGE: eastwar_worldmap_topmenu_01.webp]`

또는

> 이 문단 아래에 `eastwar_worldmap_topmenu_01.webp` 삽입

필요 없는 이미지나 비슷한 이미지가 여러 장이면 억지로 모두 사용하지 않는다.

사용하지 않는 이미지도 별도로 알려준다.

---

## 7. 한국어판과 영어판

기본은 한국어 개발일지를 먼저 완성한다.

필요할 경우 동일한 구조와 의미로 영어판도 작성한다.

영문판은 한국어 문장을 그대로 직역하지 않는다.

Steam 이용자나 해외 인디게임 개발 블로그 독자가 읽었을 때 자연스러운 **게임 개발일지 스타일의 영어**로 다시 작성한다.

다만 한국어판에 없는 새로운 내용을 임의로 추가하지 않는다.

---

## 8. 최종 산출물 형식

작업 완료 시 가능하면 다음 순서로 제공한다.

### A. 개발일지 제목
- 메인 제목
- 필요 시 부제 또는 소제목

### B. 한국어 개발일지 본문
- 소제목 포함
- 이미지 삽입 위치 표시

### C. 이미지 파일명 목록
| 순서 | 기존 이미지 설명 | 최종 파일명 | 사용 여부 |
|---|---|---|---|

### D. 이미지 배치 순서
본문 어느 위치에 어떤 이미지를 넣을지 정리

### E. 영어판
필요할 경우 작성

### F. 블로그 반영용 최종 작업지시문
김작이 이미지 파일명을 변경해 로컬 폴더에 넣고 GitHub에 업로드한 뒤 Claude Code 또는 Codex에 그대로 전달할 수 있는 형태로 작성한다.

---

## 9. 작업 시작 규칙

김작이 자료를 여러 차례에 나눠 올릴 수 있으므로 중간에 성급하게 글을 완성하지 않는다.

김작이 다음과 같이 말하면 자료 입력이 끝난 것으로 판단한다.

> **“자료 다 올렸어. 작업해.”**

그 전까지는 업로드된 자료를 확인하고 필요한 경우에만 간단히 정리한다.

---

## 10. 최종 검수

개발일지를 완성하기 전에 다음을 확인한다.

- 작업의 시작 이유가 보이는가
- 기존 문제점이 무엇이었는지 이해되는가
- 실제 수정 과정이 구체적인가
- 김작의 직접 작업과 판단이 살아 있는가
- AI가 모든 작업을 자동으로 한 것처럼 보이지 않는가
- 이미지 흐름이 Before → 과정 → After를 잘 보여주는가
- 동일한 내용이 반복되지 않는가
- 기존 EASTWAR 개발일지와 자연스럽게 이어지는가
- 게임 개발 과정의 변화와 성취가 독자에게 전달되는가
- 다음 작업 방향이 자연스럽게 연결되는가
