# 0. THINK의 한 줄 정의

> **THINK는 완성된 지식을 전시하는 공간이 아니라, 창작자가 일하고 흔들리고 판단하고 다시 나아가는 과정에서 실제로 생긴 생각을 기록하는 곳이다.**

따라서 THINK 글은 너무 매끈한 칼럼처럼 만들지 않는다.

핵심은:

- 실제 있었던 대화
- 실제 있었던 작업
- 실제 고민
- 실제 선택
- 그날의 감정과 판단
- 거기서 건진 생각

이다.

“좋은 글처럼 보이게” 꾸미는 것보다 **김작이 실제로 어떻게 생각했는지가 남는 것**을 우선한다.

---

# 1. THINK 전체 구조

현재 공식 THINK 구조:

```text
03 THINK
├─ 03–A AI 코치들과의 수다
├─ 03–B 아침 말씀 with 채코치
└─ 03–C 개인 에세이
```

보조/레거시 페이지:

```text
think/architect-notes.html
```

`architect-notes.html`은 현재 공식 03–A/B/C 메뉴에 포함되지 않으므로, 별도 요청 없이 공식 THINK 구조에 다시 편입시키지 않는다.

---

# 2. THINK index의 역할

파일:

```text
think/index.html
```

THINK index는 세 하위 카테고리를 소개하고, 최신 THINK 글 일부를 `assets/js/posts-data.js`에서 동적으로 가져온다.

현재 `THINK_POSTS`에 포함되는 `catKey`:

```text
ai-coach
morning-word
personal-essay
```

THINK 최신글은:

```js
THINK_POSTS.slice(0,5)
```

방식으로 노출된다.

따라서 `ALL_POSTS`는 **newest first**를 유지해야 한다.

# 3. THINK 공통 상세페이지 문법

THINK 상세글은 대체로 다음 공통 구조를 사용한다.

```text
Back link
Meta
Title
Subtitle
Byline
Body
Signature
Footer
```

주요 class:

```text
.post
.post__back
.post__meta
.post__title
.post__subtitle
.post__byline
.post__body
.post__sig
```

내용에 따라 사용:

```text
.dialogue
.speaker
.callout
.post__photo
.post__time
```

새 글을 만들 때는 **같은 카테고리의 가장 최근 상세글을 복제**하고 텍스트만 교체하는 방식을 우선한다.

새 THINK 글 하나 때문에 전체 post CSS를 리디자인하지 않는다.

# 4. THINK 공통 글쓰기 원칙

## 4.1 실제 경험 우선

사용자가 실제로 말한 내용과 실제 있었던 일을 기반으로 쓴다.

금지:

- 사용자가 말하지 않은 감정 추정
- 드라마틱하게 보이기 위한 사건 창작
- AI가 임의로 추가한 회고
- “분명 이런 생각도 했을 것이다” 식의 보강
- 당시엔 없던 통찰을 과거에 있었던 것처럼 소급 삽입

필요한 내용이 없으면 “자료에 없음”으로 둔다.

---

## 4.2 대화의 말맛을 살린다

THINK는 딱딱한 기술 문서가 아니다.

특히 AI 코치 글이나 아침 말씀에서는:

- 실제 표현
- 농담
- 망설임
- 반복해서 고민한 핵심 문장
- 그날의 말투

를 적절히 살린다.

단, 원문 transcript를 그대로 붙이지 않는다.

읽는 흐름을 위해:

- 중복
- 도구 실행 대화
- 의미 없는 맞장구
- 똑같은 내용의 반복

은 편집한다.

---

## 4.3 “예쁘게 정리”보다 “왜 이 생각까지 왔는가”

THINK 글의 핵심은 결론보다 과정이다.

가능하면 다음 흐름이 보이게 한다.

```text
상황
→ 고민
→ 대화/생각
→ 충돌
→ 새로 보인 것
→ 지금의 판단
```

# 5. 03–A AI 코치들과의 수다

목록:

```text
think/ai-coach.html
```

상세:

```text
posts/think/ai-coach-NNN.html
```

---

## 5.1 성격

AI 코치들과의 수다는 단순 AI transcript 보관함이 아니다.

핵심은:

> **AI와 대화하는 동안 김작의 생각이 어떻게 움직였는가**

이다.

주요 등장 가능:

- 채코치(ChatGPT)
- 클코치(Claude)
- 잼코치(Gemini)
- 기타 AI

---

## 5.2 어떤 대화를 글로 올릴 것인가

다음 중 하나 이상이 있을 때 글감이 된다.

- 새로운 창작 방법론이 생김
- 작품을 보는 기준이 바뀜
- AI 협업 방식에 대한 통찰
- 개발/창작의 막힘을 풀어낸 대화
- 인간과 AI에 대한 생각
- 기술 변화에 대한 고민
- 김작 본인의 태도나 방향이 바뀐 순간
- 나중에 다시 읽을 가치가 있는 결정

단순 정보 질문/답변은 기본적으로 THINK 글감이 아니다.

---

## 5.3 글 구조

권장 구조:

```text
1. 왜 이 대화를 시작했는가
2. 처음 김작이 던진 질문
3. 대화가 예상과 다르게 흘러간 지점
4. 핵심 대화 발췌
5. 김작이 새로 보게 된 것
6. 이후 실제 작업/태도에 미친 영향
```

필요하면 `.dialogue`를 사용한다.

예:

```html
<div class="dialogue">
  <p><span class="speaker">KIMJAK</span>...</p>
  <p><span class="speaker">CHATCOACH</span>...</p>
</div>
```

---

## 5.4 편집 규칙

원문 대화에서:

살린다:
- 결정적인 질문
- 전환점이 된 답
- 김작다운 표현
- 웃긴 순간
- 감정 변화
- 핵심 비유

줄인다:
- 반복
- 이미 앞에서 설명한 맥락
- 파일 작업 지시
- 툴 실행
- 확인용 맞장구

---

## 5.5 제목 문법

AI 코치 글은 제목 자체가 질문/사건/통찰이 되도록 한다.

예시 성격:

- `로봇은 언제 감정을 갖게 될까`
- `2026년 6월 30일. 데스벨리 끝자락에서`
- `AI 코치들과의 수다 — 프롤로그`

제목 앞에 억지로 “AI와의 대화:” 같은 설명형 prefix를 붙이지 않는다.

---

## 5.6 목록 문법

현재 목록 row는 대략:

```text
번호 · 유형
제목
부제
날짜
```

예:

```text
09 · 대화록
로봇은 언제 감정을 갖게 될까
관측이 감정을 완성한다 — 잼코치와의 대화
2026 · 06 · 10
```

신규 글은 현재 운영 원칙상 **최신 글을 상단**에 둔다.

단, `ai-coach.html`은 레거시 삽입 순서가 일부 섞여 있으므로 새 글 추가와 별도로 전체를 자동 재정렬하지 않는다.

# 7. 아침 말씀의 핵심 정체성

아침 말씀은 “오늘의 성경구절” 콘텐츠가 아니다.

핵심은:

> **김작의 실제 하루를 성경 말씀과 함께 기록하는 작업 일지 + 신앙 일기**

다.

따라서 반드시 **그날의 현실**이 있어야 한다.

예:

- 오늘 어떤 작품을 작업하는가
- 어제 무엇을 끝냈는가
- 어떤 미팅/제출/도전이 있는가
- 무엇이 두렵거나 기대되는가
- 어떤 다짐을 했는가
- 가족/운동/여행/일상의 사건
- 그 상황에 맞는 말씀

---

# 8. 아침 말씀 기본 글 구조

아침 말씀은 너무 정형화하면 생명력이 죽는다.

하지만 기본 뼈대는 다음이 좋다.

```text
1. 오늘 아침 상황
2. 어제까지의 흐름
3. 오늘 해야 할 일
4. 김작이 가진 마음/다짐
5. 채코치와의 짧은 대화
6. 오늘의 말씀
7. 그 말씀을 오늘 상황과 연결
8. 짧은 출발 문장
```

모든 글에 1~8을 기계적으로 다 넣을 필요는 없다.

그날 실제 대화의 리듬을 우선한다.

---

# 9. 아침 말씀에서 성경 구절을 다루는 법

## 9.1 선택 기준

말씀은 그날의 실제 상황과 맞아야 한다.

예:

- 두려움 → 담대함/의탁
- 오래 버티는 시기 → 인내/때/수고
- 새로운 출발 → 길/부르심/전진
- 피드백과 성장 → 지혜/훈계
- 제출/결과를 기다림 → 맡김/평안
- 힘든 작업 → 손의 수고/성실

---

## 9.2 같은 구절 반복 주의

김작은 아침 말씀을 지속적으로 기록하므로, 이미 최근에 사용한 구절을 무의식적으로 반복하지 않는다.

새 글 작업 때 가능하면 최근 아침 말씀 목록/상세글을 확인한다.

---

## 9.3 말씀을 억지로 성공 예언처럼 쓰지 않는다

금지:

- “이 말씀은 반드시 이번 계약이 된다는 뜻”
- “하나님이 이 프로젝트의 성공을 약속”
- “이 구절 때문에 결과는 정해졌다”

대신:

- 어떤 태도로 오늘을 살아갈지
- 무엇을 붙잡을지
- 무엇을 내려놓을지

에 연결한다.

# 10. 아침 말씀 문체

아침 말씀의 글은 지나치게 설교조로 만들지 않는다.

김작과 채코치의 실제 대화 감각을 유지한다.

가능한 톤:

- 살아 있음
- 가볍게 웃을 수 있음
- 하지만 다짐은 진지함
- 과장된 감상문 금지
- 자기계발 문구처럼 만들지 않음

---

# 11. 아침 말씀 제목 문법

제목은 그날의 **핵심 사건/다짐/문장**에서 뽑는다.

현재 실제 스타일 예:

- `9월 출발!`
- `제출의 날, 그리고 다짐`
- `8월은 활주로, 9월은 이륙`
- `잘 써야 한다가 아니라, 피하지 않고 쓴다`
- `포기는 배추 셀 때나 하는 거지`

즉 제목 자체가 그날의 기억 장치가 되어야 한다.

---

# 12. 아침 말씀 부제 문법

부제에는 “오늘 무슨 날이었는지”를 좀 더 구체적으로 기록한다.

예:

```text
하얗게 불태울 준비 끝. 달리자!
8월 마지막 일요일, 동해를 보고 다짐한 것
대본 대장정과 삼국워 모두의 창업 도전 시작
```

제목과 같은 말을 반복하지 않는다.

# 16. 개인 에세이의 정체성

개인 에세이는 THINK 중 가장 “완성된 글”에 가깝다.

하지만 문학적 포장을 위해 사실을 바꾸지는 않는다.

핵심 주제:

- AI 시대의 창작
- 작가로서의 변화
- 1인 스튜디오
- AI 협업
- 개발과 창작의 결합
- 실패와 배움
- 김작 개인의 생각

---

# 17. 에세이 글 구조

정답형 칼럼보다는 개인 경험에서 시작하는 편이 좋다.

권장:

```text
구체적인 실제 사건
→ 그때 든 생각
→ 과거의 나와 비교
→ AI/창작/개발에 대한 통찰
→ 지금의 결론
```

에세이가 길어져도 괜찮지만, 한 글에 주장 5개를 욱여넣지 않는다.

**한 글 = 한 중심 생각**

을 우선한다.

---

# 18. 에세이 제목 문법

설명형이어도 되지만 반드시 김작의 실제 관점이 드러나야 한다.

현재 성격 예:

- `AI 작문 활용법 - 창작, 코치, 듀얼모드`
- `코더에서 PM으로, AI의 다음 단계`

너무 범용적인 제목:

- “AI에 대한 생각”
- “요즘 느낀 점”
- “나의 개발 이야기”

같은 것은 피한다.

# 21. THINK에서 이미지 사용

THINK는 이미지 중심 섹션이 아니다.

이미지는 **실제 이야기를 더 잘 이해시키는 경우에만** 넣는다.

예:

- 실제 여행/작업 사진
- 당시의 기록 이미지
- 의미 있는 스크린샷
- 에세이에서 꼭 필요한 참고 이미지

금지:

- 글이 심심해 보여 장식용 이미지 추가
- AI 생성 이미지를 실제 사건 사진처럼 사용
- 글과 직접 관계없는 분위기컷

---

# 22. THINK 상세 페이지 이미지 문법

기존 `.post__photo`가 있다.

보통:

```html
<div class="post__photo">
  <img src="..." alt="..." />
</div>
```

페이지별로 width와 style이 다를 수 있으므로 동일 카테고리 최신 상세글을 복제한다.

---

# 23. THINK에서 대화 인용

대화는 `dialogue` 구조를 우선한다.

김작의 실제 문장을 살릴 수 있지만:

- 맞춤법을 과도하게 교정해서 말맛을 없애지 않는다.
- 의미 없는 군더더기는 정리한다.
- AI 답변을 길게 통째로 복붙하지 않는다.
- 핵심 대화만 사용한다.

---

# 24. THINK에서 callout 사용

`.callout`은 글의 핵심 문장/정리/작업 원칙을 강조할 때 사용한다.

남용 금지.

한 글에서 모든 문장을 명언처럼 만들지 않는다.

---

# 25. `assets/js/posts-data.js` THINK 규칙

새 THINK 글은 `ALL_POSTS` 맨 앞에 넣는다.

예:

```js
{
  url: 'posts/think/morning-word-035.html',
  catKey: 'morning-word',
  cat: 'Morning Word',
  title: '...',
  sub: '...',
  date: '2026-09-04',
  dl: '2026 · 09 · 04'
}
```

카테고리:

```text
ai-coach
morning-word
personal-essay
```

다른 이름을 새로 만들지 않는다.

---

# 26. THINK index 최신글 반영

`think/index.html`은 `THINK_POSTS`에서 최신 5개를 표시한다.

따라서 새 THINK 글을 등록했는데 index 최신글에 안 나오면 먼저:

```text
assets/js/posts-data.js
```

를 의심한다.

---

# 27. 목록 정렬의 현행 규칙

Master Guide와 동일하게 THINK는 기본적으로:

> **최신 글 위 / 오래된 글 아래**

를 따른다.

`morning-word.html`, `personal-essay.html`, `posts-data.js`는 현재 이 원칙을 사용한다.

`ai-coach.html`은 과거 순서가 일부 혼재되어 있으므로 별도 정리 작업 없이 기존 전체 순서를 자동으로 뜯어고치지 않는다.

---

# 28. THINK 페이지를 만들 때 템플릿 선택

새 상세글을 만들 때:

## AI 코치 글
가장 최근 `posts/think/ai-coach-NNN.html`

## 아침 말씀
가장 최근 `posts/think/morning-word-NNN.html`

## 개인 에세이
가장 최근 `posts/think/think-NNN.html`

을 기준으로 한다.

다른 카테고리 템플릿을 섞지 않는다.

---

# 29. 새 THINK 글 작업 흐름

## 1단계 — 자료 받기

김작이:

- 원문 메모
- 채팅 대화
- 사진
- 넣고 싶은 핵심 문장
- 말씀
- 날짜

를 제공한다.

---

## 2단계 — 현재 사이트 확인

채코치는 먼저 GitHub에서:

```text
같은 카테고리 최신 상세글
같은 카테고리 목록
posts-data.js
```

를 확인한다.

---

## 3단계 — 편집

다음 기준으로 글을 만든다.

```text
사실 보존
말맛 보존
중복 제거
핵심 흐름 강화
없던 사실 추가 금지
```

---

## 4단계 — 제목/부제

제목은 글의 핵심 기억.

부제는 구체적 맥락.

---

## 5단계 — 코드 반영 지시문

Claude Code/Codex에 넘길 수 있도록:

- 새 상세 파일
- 목록 파일
- posts-data
- 번호
- 날짜
- 링크

를 명시한다.

---

# 30. 자료 업로드 중 최종 작성 금지

김작이 여러 메시지로 자료를 올릴 수 있다.

다음 말이 나오기 전까지 최종 작성하지 않는다.

> **“자료 다 올렸어. 작업해.”**

# 31. THINK 최종 산출물

가능하면 다음 순서:

## A. 분류
```text
03–A / 03–B / 03–C
```

## B. 제목/부제

## C. 최종 본문

## D. 사용한 실제 대화/사진 위치

## E. 목록용 title/sub/date

## F. posts-data entry

## G. Claude Code/Codex용 반영 지시문

# 32. AI 코치 글 검수

```text
[ ] 단순 transcript가 아닌가
[ ] 대화를 시작한 이유가 보이는가
[ ] 김작의 생각이 변한 지점이 있는가
[ ] 실제 대화의 말맛이 살아 있는가
[ ] AI 답변을 과도하게 길게 붙이지 않았는가
[ ] 결론을 AI가 대신 내려준 것처럼 보이지 않는가
```

---

# 33. 아침 말씀 글 검수

```text
[ ] 그날 실제 일이 보이는가
[ ] 단순 성경구절 게시물이 아닌가
[ ] 오늘의 고민/작업과 말씀이 연결되는가
[ ] 최근 사용 말씀을 무심코 반복하지 않았는가
[ ] 성공 예언처럼 과장하지 않았는가
[ ] 김작과 채코치의 실제 대화 리듬이 남아 있는가
[ ] 제목만 봐도 그날이 기억되는가
```

---

# 34. 개인 에세이 검수

```text
[ ] 한 글에 중심 생각이 하나인가
[ ] 실제 경험에서 출발하는가
[ ] 너무 교훈적인 칼럼이 되지 않았는가
[ ] AI가 대신 써준 일반론처럼 보이지 않는가
[ ] 김작의 관점이 분명한가
[ ] 없던 사건/감정을 추가하지 않았는가
```

# 36. 절대 하지 않는 것

- THINK를 뉴스레터처럼 획일화
- 모든 글에 같은 소제목 구조 강제
- 실제 대화보다 AI가 만든 문장을 더 많이 넣기
- 김작이 하지 않은 생각을 “김작은 깨달았다” 식으로 추가
- 신앙 글을 성공 확언/예언처럼 만들기
- 아침 말씀을 설교문처럼 만들기
- AI 코치 글을 transcript dump로 만들기
- 에세이를 자기계발 칼럼처럼 만들기
- 기존 legacy 파일명 정리
- 사용자 요청 없이 오래된 글 전체 재편집
- 사용자가 자료 다 올리기 전에 완성본 작성

---

# 37. THINK 작업 시 채코치의 역할

채코치는 THINK에서 “대필자”보다 **편집자 + 기록자 + 구조 코치**에 가깝다.

즉:

- 김작의 말을 더 김작답게 정리
- 의미 있는 흐름을 찾아냄
- 반복은 걷어냄
- 당시의 실제 생각은 보존
- 나중에 읽어도 그날을 떠올릴 수 있게 정리

한다.
