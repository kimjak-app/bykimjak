Getting EASTWAR Ready for Export

A Cleanup Roadmap Before the Prototype Wraps, and How Export Actually Works

July 30, 2026

Alongside the Build, Finishing Prep Begins

With T01 and T02 wrapped, Land Battle and World Map MVP detail work has kept rolling forward. But as each feature gets finished, something else started nagging at me. Test scenes thrown together along the way, scripts written in a hurry, images that quietly stopped being used, debug print statements left in the code — a lot has piled up since the early days of development.

Shipping an export as-is would still run fine. But the more the project grows, the more that leftover clutter becomes a real management burden — a point that came back up talking it through with 채코치. So August got replanned — not as a pause on feature work, but as running cleanup and finishing prep alongside ongoing MVP completion.

Here's the conversation where that cleanup roadmap got worked out.

How Export Actually Works

Worth covering the export process itself while we're at it. Getting a runnable build out of Godot generally goes like this.

  • 1. Install Export Templates — under Editor → Manage Export Templates, grab the template matching your current Godot version first. A version mismatch blocks export entirely.
  • 2. Go to Project → Export and use Add to bring in the target platform (Windows, macOS, Web, etc.).
  • 3. Check platform-specific preset details — icon, executable name, resolution, and so on.
  • 4. Hit Export Project to produce the actual build. If test scenes or unused resources are still sitting in the project at this point, the build just gets bloated and the shipped result gets messy — which is why cleanup has to come before export, not after.
  • 5. Once the build finishes, always run it in a separate environment (a different folder or a different machine). Things that run fine inside the editor sometimes break in an actual build due to path issues.

Exporting without cleanup first would still produce a working game. But every future fix or next-version prep keeps getting slowed down by an uncleaned project. So this time, the order gets followed properly: cleanup → bug fixes → export test.

What's Next

August is shaping up like this.

  • 1. Finish the remaining prototype features (Land Battle, World Map, Domestic, Tech Tree MVPs) within August.
  • 2. Go through the entire project with 채코치 — folder structure, unused scenes, duplicate scripts, autoload structure, resources, naming, all of it.
  • 3. Go folder by folder deciding delete, move, or rename. Anything uncertain moves to Test/Old first instead of getting deleted outright.
  • 4. Finish with an export test to confirm everything holds.

Once this is done, EASTWAR stops being a refactoring target or a prototype — it becomes one real, playable game.
