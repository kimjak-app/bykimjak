Dev Log · #028

삼국워 Export 준비

프로토타입 마무리를 위한 정리 로드맵과 export 하는 법

2026년 07월 30일

만드는 과정과 함께, 마무리 준비 단계 시작

T01, T02를 완결하고 나니 육상전투·월드맵 MVP 디테일 작업이 계속 이어지고 있다. 그런데 기능을 하나씩 완성해가면서 슬슬 다른 문제가 눈에 밟히기 시작했다. 테스트용으로 만들어뒀던 씬, 급하게 짜둔 스크립트, 어느 순간부터 안 쓰는 이미지, 디버그용으로 넣어둔 print문들 — 개발 초반부터 지금까지 쌓인 것들이 꽤 많다.

이 상태로 그냥 Export해도 게임 자체는 돌아간다. 하지만 프로젝트가 커질수록 이런 잔재가 관리 부담이 된다는 걸 채코치와 얘기하면서 다시 확인했다. 그래서 8월 계획을 다시 잡았다. 기능 개발을 멈추는 게 아니라, MVP 완성 작업과 나란히 정리·마무리 준비를 병행하기로 했다.

이번 대화는 그 정리 로드맵을 채코치와 짠 내용이다.

김작맞아. 그게 프로토타입 완성 과정에서 의외로 시간이 많이 드는 작업이야.
지금은 개발하면서 이런 것들이 많이 남아 있을 가능성이 커.

김작테스트용 Scene
테스트용 GDScript
사용 안 하는 이미지
예전 버전 UI
임시 사운드
테스트 버튼
디버그 코드(print(), 테스트 변수 등)

김작이걸 그대로 두고 Export하면 게임이 돌아가긴 하지만, 프로젝트가 점점 관리하기 어려워져.
내가 추천하는 순서는 이래.

김작1. 새 기능 추가 중단
2. 테스트 파일 정리
3. 사용하지 않는 리소스 삭제
4. 폴더 구조 정리
5. 버그 수정
6. Export 테스트

김작특히 삼국워처럼 프로젝트 규모가 커지면 폴더를 깔끔하게 정리하는 게 중요해. 예를 들면,

    Battle/
    WorldMap/
    UI/

    Battle/
    World/
    Managers/

Assets/
    Images/
    Video/
    Audio/

김작이런 식으로만 정리해도 나중에 작업 속도가 훨씬 빨라져.
그리고 하나 더 추천하고 싶은 건 Test 폴더를 따로 만드는 것이야.

김작Scenes/
Test/
Old/

김작당장 지우기 불안한 파일은 Old나 Test 폴더로 먼저 옮겨. 게임이 정상적으로 돌아가는 걸 확인한 뒤에 삭제하면 훨씬 안전해.

김작8월은 사실 기능을 만드는 달이라기보다 '정리하고 완성하는 달'이 될 가능성이 커 보여. 그 작업이 끝나면 삼국워는 정말 하나의 실행 가능한 게임에 가까워질 거야.
이 정리 네가 해줄 수 있지?

채코치응, 그건 내가 충분히 도와줄 수 있어.
다만 내가 직접 네 PC의 파일을 삭제하거나 Godot 프로젝트를 자동으로 정리할 수는 없어. 대신 같이 리뷰하면서 어떤 파일을 남기고, 어떤 파일을 삭제하거나 합칠지는 꽤 깊게 도와줄 수 있어.

채코치예를 들어 네 프로젝트를 받으면 이런 식으로 진행할 수 있어.

채코치폴더 구조 검토
사용하지 않는 Scene 찾기
중복 스크립트 정리
테스트용 코드와 실제 코드 분리
오토로드(싱글톤) 구조 검토
리소스(이미지, 사운드, 영상) 정리
변수명, 함수명, 파일명 통일
Export 전에 필요한 설정 점검

채코치특히 너처럼 프로젝트가 어느 정도 커진 상태에서는 "리팩터링 단계"가 한 번 꼭 필요해.
내가 추천하는 방법은 이거야.

채코치1. 8월에 프로토타입 기능을 모두 완성한다.
2. 그다음 프로젝트 전체를 나와 함께 한 바퀴 돈다.
3. 폴더 하나씩 보면서 "이건 삭제", "이건 이동", "이건 이름 변경"을 결정한다.
4. 마지막에 Export 테스트를 한다.

채코치이렇게 하면 무작정 파일을 지우는 것보다 훨씬 안전해.

Export는 실제로 어떻게 하나

이참에 Export 자체도 짚어두려 한다. Godot에서 실행 파일을 뽑는 과정은 크게 이렇다.

  • 1. Export Templates 설치 — Editor 메뉴 → Manage Export Templates에서 현재 Godot 버전과 맞는 템플릿을 먼저 받아둬야 한다. 버전이 안 맞으면 Export 자체가 안 된다.
  • 2. Project → Export 메뉴에서 Add로 원하는 플랫폼(Windows, macOS, Web 등)을 추가한다.
  • 3. 플랫폼별 프리셋에서 아이콘, 실행 파일명, 해상도 같은 세부 설정을 확인한다.
  • 4. Export Project를 눌러 실제 빌드를 만든다. 이때 프로젝트 안에 테스트 씬이나 안 쓰는 리소스가 그대로 남아있으면 빌드 용량만 커지고 배포용 결과물이 지저분해진다 — 그래서 정리가 Export보다 먼저 와야 한다.
  • 5. 빌드가 끝나면 반드시 별도 환경(다른 폴더 또는 다른 PC)에서 실행해본다. 에디터 안에서는 멀쩡히 돌아가던 게 실제 빌드에서는 경로 문제로 깨지는 경우가 종종 있다.

정리 없이 Export를 먼저 해도 게임 자체는 돌아간다. 하지만 이후에 뭔가 고치거나 다음 버전을 준비할 때, 정리 안 된 프로젝트는 매번 발목을 잡는다. 그래서 이번엔 순서를 지키기로 했다 — 정리 → 버그 수정 → Export 테스트.

앞으로

8월 계획은 이렇게 잡혔다.

  • 1. 8월 안에 프로토타입 기능(육상전투·월드맵·내정·테크트리 MVP)을 마저 완성한다.
  • 2. 그다음 채코치와 프로젝트 전체를 한 바퀴 돈다 — 폴더 구조, 안 쓰는 씬, 중복 스크립트, 오토로드 구조, 리소스, 네이밍까지.
  • 3. 폴더 하나씩 보면서 삭제·이동·이름 변경을 결정한다. 애매한 건 바로 지우지 않고 Test/Old 폴더로 먼저 옮긴다.
  • 4. 마지막에 Export 테스트로 확인한다.

이 과정이 끝나면 삼국워(EASTWAR)는 리팩토링 대상도, 프로토타입도 아닌, 정말 하나의 실행 가능한 게임이 된다.
