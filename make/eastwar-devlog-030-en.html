Dev Log · #030

Battle On Screen Finally Came Alive

From Cutin Standardization to Multi-Enemy AI — Presentation Becomes a System

July 31, 2026

How Sharp Does a Cutin Need to Be?

The first thing that came up when starting hero cutins was a technical question. Using Cheok Jun-gyeong as the test sample, multiple resolutions got tested. At 1280×720, 30fps, there was no screen breakup, armor/face/sword/background detail all held up, and there was no color bleeding or block collapse. 1080p, on the other hand, carried real playback strain — whether that was the 1080p Theora playback itself or a mismatch between that conversion and the Godot decoder wasn't fully clear, but either way the playback instability risk far outweighed any visible gain.

So 720p got locked in as the standard. The final judgment criterion was one thing: does it hold up against the original to the naked eye. The moment Cheok Jun-gyeong's "Sword King's Breakthrough" scene landed, it confirmed the direction was right. With the general's name, skill name, one line of dialogue, and quick entry/exit polished, this could become EASTWAR's signature presentation.

Perfect One First, Then Scale to Thirteen

Finishing the cutin followed a set order. First there was the raw action base image.

Title font and layout got tested on top of it.

Combining the two produced Gyebaek's final cutin.

The approach was to lock everything — resolution, font, position, timing — around a single general, Cheok Jun-gyeong, before expanding to the other 12. Fonts got set: NotoSerifKR-Bold (a serif style) for the general's name, a sans-serif for the dialogue line. Dialogue font size stayed at 29, with position and scale driven by scene-authored transforms. These approved values — CutinStage position, name position, unique-skill PNG position, dialogue position, and the entry/hold/exit timing — got committed as a baseline that could not visually change during the later componentization pass.

Only after that baseline was locked did the Cheok Jun-gyeong-only debug preview get promoted into a shared cutin component — video, name, skill PNG, dialogue, position, scale, and timing all folded into one reusable scene where only per-general data swaps in. The condition was that Cheok Jun-gyeong's master screen and behavior stayed exactly identical through this change.

Next came fixing two mislabeled skill PNG filenames (Kim Yu-sin's samguk→samhan, Gyebaek's baekje_buheung→hwangsan_beol), batch-converting all 13 MP4s into the approved 720p Theora OGV format, registering all 13 generals' data into a single registry, and building an F6 cycling preview through the shared component. This stage split across three roles — 채코치 handled design lock-in and result audits, Work/Codex handled the local work (FFmpeg conversion, Godot verification, commits), and Kimjak handled actual F6 visual QA and final sign-off.

One general needed individual review in the cycling preview: Gwanggaeto the Great. His dialogue line ran 504px wide against the shared authored width of 396px, and while Godot auto-expanded the minimum width to keep it on one line, it needed a visual check to confirm it didn't look oversized or collide with the title or the character compared to the other 12, all of whom landed within the shared range numerically.

Fonts Need Licensing Checks Too

Whether Noto Serif KR, the font used in the cutins, was safe for a commercial game got confirmed upfront. The official release is under the SIL Open Font License 1.1 (OFL), which permits bundling and embedding the font in commercial game distribution. Two conditions apply, though — the font files can't be sold standalone, and any distribution bundling it into the game needs a copyright notice and a copy of the OFL license included.

The Korean subset, Noto Serif KR, was pulled from the official GitHub release page (notofonts/noto-cjk), with the Bold and SemiBold weights plus OFL.txt saved into the repo under assets/fonts/noto_serif_kr/, and the copyright notice separately documented in THIRD_PARTY_NOTICES.md at the project root. Since Godot imports this font as a game resource and packages it into the executable/PCK at build time, users never need to install the font themselves.

From a Pretty Preview to an Actual Game System

Once the cutin assets and shared structure were done, the real work began. Everything up to this point had been "showcase preview" — now it had to be wired into the actual battle flow. The failure modes got mapped out in advance: a skill effect firing before its cutin plays, a player clicking another action mid-cutin, an AI turn stalling or running twice, momentum getting deducted twice, a cutin playing despite a failed validation, battle not resuming after a cutin ends, or overlapping cutins on consecutive triggers.

So one principle got locked as the rule:

Skill execution conditions validated → execution committed → momentum deducted once → battle flow locked → cutin plays → cutin-finished signal → existing skill effect processing continues → battle flow unlocked

The key point: the cutin isn't what triggers the skill's calculation — it's an asynchronous presentation step for an execution that's already been confirmed. And it must never play on a cancellation, a target error, or a failed validation — only once a valid execution is confirmed. Rather than building separate cutin code for player and AI, both route through the same play_unique_skill_cutin(hero_id, skill_id) function. Once wired in, QA was planned across both player and AI for self-buff types, single-target types, AoE types, evasion/immunity/partial-effect-failure cases, and consecutive skill activations.

Two Bugs Caught Along the Way

Alongside the cutin work, two other issues got fixed.

Garrisoned general portraits: in the roster of generals stationed at Sabi, five portraits — Uija, Gyebaek, Heukchi Sangji, Kim Chun-chu, and Jang Bogo — showed a question-mark placeholder instead of the actual image. Only Kim Yu-sin displayed correctly. The list, names, and stats all rendered fine — only the portrait lookup was failing. Rather than creating new image assets, the fix restored parity in hero ID, payload, and portrait lookup during the transition from battle result back to a world map garrison.

Korean localization of skill effects: all 39 generals' unique skills got fully audited for on-screen display text. English text had been confirmed in production for three of them — Jang Bogo, Gwanggaeto the Great, and Uija — but rather than fixing just those three, every one of the 39 got checked. Activation notifications, effect names, buff/debuff names, status effect names, damage/heal/defense effect text, duration text, battle logs, floating combat text, and tooltips all got covered. The fix separated internal IDs from user-facing display strings so player and AI share the same formatter. The result: zero English UI exposure, Korean-verified battle logs, and 5 GDScript warnings visible in a screenshot cleared along the way.

The Real Big Bug — Only One Enemy Ever Acting

The most impactful fix was separate from all this. In a 1-vs-4 battle, after a single enemy acted, control unconditionally returned to the player's turn — the remaining three enemies never got a chance to act at all.

The fix split into two stages. First, every enemy-action-end point got unified through a shared helper, and the enemy turn now continues as long as any enemy hasn't acted yet — control only returns to the player once every living enemy has acted, and a new round only starts once both sides have fully acted. Only after this stage (T06-11A) passed F5 QA did the second stage (T06-11B) verify whether the existing approach/surround system (destination/engagement reservation) actually worked correctly across multiple enemy units.

An important discovery came out of this: no new surround AI was built — the fix simply unblocked a turn-orchestration bug that had been suppressing an already-existing system. Sure enough, the existing approach logic alone produced three enemies converging simultaneously once unblocked. Multiple enemies could now share the same target, destination and engagement cell duplication got prevented, and the existing flank (1.15x) and rear (1.30x) multipliers stayed unchanged and verified.

Both stages locked with a final F5 PASS. Numeric advantage in battle is now something players can actually feel — enemies no longer bunch up head-on; they approach from multiple directions.

What's Next

The cutin system has cleared visual QA; what remains is wiring it into actual skill activation and running combined player/AI QA. Once that's done, cutins stop being a pretty preview screen and become a real part of EASTWAR's battle system.
