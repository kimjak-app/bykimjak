Dev Log · #036

Getting a Second Face

Swapping the World Map's Design for a Second Time, and Adding Territory Display

August 27, 2026

Starting With the Background

With the first design pass settled, the next stretch of work replaced the world map's background art itself. The goal for this stage was singular: lock a new full background image to a 4096×2304 baseline, split it into four, and swap the existing background texture in WorldMap_UI_Test only. The existing UI overlay stayed untouched — this was purely an "art quality verification test" to confirm clicks, markers, and info-panel readability still held up against the new background.

Once the new image arrived, the same approach from the first pass carried over. A test-only controller got added to slice the 4096×2304 image at runtime into four 2048×1152 regions — top-left, top-right, bottom-left, bottom-right — and place each at 0.5x scale. This controller only touches the new background file; it doesn't modify the existing background system or Production code at all. Only that one new controller got added to the test scene — the existing Production world map, left/right info panels, treasury/tech/readability controllers, the Stable HUD, and the turn-transition guard all stayed exactly as they were.

Color Seeps Into the Land

With the background in place, territory display came next. The concept was simple: lay a semi-transparent territory layer over the 2048×1152 world, and for every pixel, calculate "which of the 13 cities is nearest to me" and tint it with that city's current faction color — a nearest-point approach.

Doing only this creates a problem, though — a region like China, with only 4 cities, ends up looking like the entire continent got carved up between them in a strange way. So one more rule got added: only color within an 80px radius of a city, leaving everything beyond that as the original terrain color (with a 30px fade for a smooth boundary). This makes densely-packed regions like Korea and Japan look like naturally connected territory, while sparse China reads as distinct circular spheres of influence around each city.

The ocean got excluded entirely. A separate black-and-white land/sea mask ensures color only applies to white areas (land), never to black areas (sea). Color intensity mattered too — painting the calculated faction color at full 100% strength would completely bury the mountain and river textures underneath, making it look like a sticker slapped on top. Dialing it down to 35% gives the terrain a thin "tinted" look instead.

The core idea: none of these four rules — nearest city, radius limit, sea exclusion, 35% opacity — got pre-rendered into a static image. The game calculates all of it in real time, every frame. That means when the city count grows from 4 to 50 later, there's no need to redraw any polygons — adjusting a single radius number automatically rebalances everything.

The implementation ended up cleaner than what was originally specified, too. The instruction had been "reuse the CITY_POSITIONS constant as-is," but the actual implementation went one step further — reading position and owner_faction_id directly from the CityLayer's actual marker nodes at runtime, instead of hardcoding a second coordinate list on the shader side. This keeps a single source of truth: if a marker's position shifts or ownership changes later, the territory shader follows automatically. The city array also moved from a fixed size of 13 to a MAX_CITIES 64 + city_count structure, leaving room to grow without needing to rewrite the code later.

The terrain source assets used for this work were prepared as separate transparent-background pieces by region — Korea, the Japanese archipelago, Manchuria, and China split into four (Huabei/Shandong, Jiangnan/Taiwan, Southwest/Hainan, Northwest) — each existing as an individual fragment before combining into one unified continental map.

The Finished Second Face

Here's the result once the background swap and territory shader both landed.

A soft blue sphere of influence spreads outward around Hanseong; Pyongyang, Gyeongju, and Sabi are each tinted with their own colors too. The same holds for the Japanese side around Osaka and Kyoto — regions with dense city clusters blend naturally into connected territory, while distant areas keep their original terrain color. This matches the target exactly: only the land immediately around each castle gets a soft faction tint, distant areas between cities stay neutral, and the ocean never gets colored at all.

What's Next

With the background map and territory display both in place, the world map now has its second face. What's left is hooking this territory system into actual ownership changes — invasion and occupation — so that the outcome of a war shows up immediately as a shift in color on the map.
