EASTWAR 개발일지 #004

Phaser를 어떻게 쓸 것인가 — 설계의 원칙

2026년 5월 1일

엔진을 골랐다고 끝이 아니었다.

Phaser.js를 쓰기로 했는데, 다음 질문이 바로 왔다.

"삼국워(EASTWAR), Phaser를 어떻게 써야 하는가?"

이게 생각보다 중요한 질문이었다. Phaser를 잘못 쓰면 나중에 Godot으로 옮길 때 다 갈아엎어야 한다. 잘 쓰면 지금 만든 코드의 핵심이 그대로 살아남는다.

채코치가 딱 하나만 기억하라고 했다.

"Phaser는 화면 담당이다. 게임 규칙은 Phaser 밖에 둬라."

Phaser의 역할을 제한했다

처음엔 Phaser 안에 다 넣고 싶었다. 전투 계산도, 이동 판단도, 도시 점령 처리도. 어차피 게임이니까 한 곳에 다 모으면 편하지 않을까 싶었다.

근데 채코치가 보여준 비교가 결정적이었다.

나쁜 구조 — 버튼을 누르면 도시 주인이 바뀌고, 화면도 바뀌고, 결과 텍스트도 바뀌는 코드가 한 덩어리로 묶여있는 것. 나중에 Godot으로 옮길 때 이 덩어리를 통째로 다시 짜야 한다.

좋은 구조 — 전투 계산은 따로, 화면 표시는 따로. 계산 코드는 Phaser에서도 Godot에서도 그대로 쓸 수 있다. 화면만 바꾸면 된다.

대본으로 치면 이렇다. 이야기(게임 규칙)와 연출(화면)이 섞여있으면 감독이 바뀔 때 대본까지 다시 써야 한다. 분리돼 있으면 감독만 바꾸면 된다.

세 가지로 쪼갰다

그날 삼국워(EASTWAR)의 구조를 세 가지로 나눴다.

Core JS — 게임의 두뇌

전투 계산, 이동 가능 여부 판단, 승패 판정, 도시 점령 처리. 이것들은 화면과 완전히 분리된 순수한 계산 영역이다. Phaser가 없어도 혼자 돌아가야 한다. 나중에 Godot으로 옮길 때 이 부분은 그대로 살아남는다.

규칙도 딱 하나 박아뒀다 — Core 안에서는 화면을 건드리는 코드를 절대 쓰지 않는다. document.querySelector나 innerHTML 같은 것들이 Core 안에 들어가는 순간 이식이 어려워진다.

Phaser — 눈에 보이는 것

전장 그리기, 부대 움직임, 공격 이펙트, 컷인. Phaser가 하는 일은 딱 여기까지다. 계산은 Core에서 받아오고, 그 결과를 화면에 보여주는 역할만 한다.

HTML — 전략 정보창

장수 목록, 도시 정보, 내정 메뉴. 문명이나 삼국지 같은 전략게임은 화면에 보이는 정보가 엄청 많다. 그걸 전부 Phaser 안에 넣으면 오히려 불편해진다. 이건 HTML로 처리하는 게 맞다.

데이터도 이식 가능하게 만들었다

구조만 쪼개는 게 아니라 데이터 형태도 신경 썼다.

전투 데이터를 이렇게 만들면 나중에 Godot에서 그대로 쓸 수 있다.

{
  battleId: "battle-hanseong-pyeongyang",
  attackerCityId: "hanseong",
  defenderCityId: "pyeongyang",
  units: [
    { id: "player-general", hp: 100, atk: 25, move: 3 },
    { id: "enemy-general", hp: 100, atk: 20, move: 3 }
  ]
}

이런 데이터 구조는 Godot에서도 거의 그대로 옮길 수 있다. 반대로 Phaser 객체 자체를 저장해버리면 이식이 거의 불가능해진다.

전체 흐름은 이렇게 됐다

HTML 월드맵
  ↓ 공격 클릭
Core: 전투 상태 생성
  ↓
Core: 이동/공격/승패 계산
  ↓
Phaser: 전투 화면 표시
  ↓
Core: 승패 결과 처리
  ↓
HTML 월드맵 복귀

나중에 Godot으로 갈 때는 이렇게 바뀐다.

Core/battle_rules.js   →  Godot BattleRules.gd
Core/battle_state.js   →  Godot BattleState Resource
Phaser/battle_scene.js →  Godot BattleScene.tscn
HTML/world_map_ui.js   →  Godot WorldMapScene.tscn

Core는 그대로 살아남고, 화면만 바뀐다.

초보자한테 진짜 하고 싶은 말

도구를 고르는 것보다 도구를 어떻게 쓸지가 더 중요하다.

Phaser를 쓰기로 했을 때 제일 먼저 한 건 Phaser 사용법을 익히는 게 아니었다. Phaser가 무슨 역할을 해야 하는지 먼저 정했다. 역할이 정해지니까 어디에 뭘 넣어야 하는지가 명확해졌다.

코딩을 모르는 내가 이 판단을 할 수 있었던 건 채코치가 설명을 쉽게 해줬기 때문이기도 하지만, 더 근본적으로는 역할을 나누는 게 중요하다는 걸 드라마 작업에서 이미 알고 있었기 때문이다.

작가, 감독, 배우, 스태프. 각자 역할이 명확해야 현장이 돌아간다. 게임도 똑같다.

"Phaser는 배우다. 연기만 해야 한다. 대본까지 쓰면 현장이 꼬인다."

삼국워(EASTWAR)는 그렇게 설계됐다.
