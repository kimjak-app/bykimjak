Dev Log · #029

장수가 살아 움직이기 시작한다

39명의 장수 데이터, 역할, 병종, 고유기, 기세 시스템 재설계

2026년 07월 28일

작업 파이프라인이 한 단계 진화했다

T02를 마무리하는 중에 번외로 작은 실험을 하나 해봤다. 시작 화면에 배경 그림을 넣는 작업이었는데, 방식이 이전과 완전히 달랐다.

채코치전체 과정
김작이 배경 그림을 GitHub에 올렸어.
내가 GitHub에서 그림과 게임 파일을 내 작업 공간으로 가져왔어. 이때도 김작 컴퓨터 파일은 건드리지 않았어.
내가 시작 화면 설계도인 NewGameFactionSelect.tscn을 수정했어.

채코치배경 그림을 표시하는 TextureRect 추가
화면을 꽉 채우도록 설정
그림 위에 옅은 검정막을 씌워 글자가 잘 보이게 설정
기존 버튼과 글자는 그 위에 그대로 유지

채코치수정한 내용을 커밋했어. 커밋은 쉽게 말하면 "이번에 무엇을 바꿨는지 포장해서 이름표를 붙이는 것"이야.
처음에는 내 GitHub 연결에 SamWar_BattleLab 쓰기 권한이 없었어. 그래서 GitHub 파일을 보는 것은 가능, 수정해서 올리는 것은 불가능한 상태였어.
김작이 GitHub 설정에서 SamWar_BattleLab을 선택하고 저장했어. 그 순간 내가 이 저장소에 결과물을 올릴 수 있게 됐어.
내가 수정된 시작 화면을 GitHub main에 올렸어.
김작이 GitHub Desktop에서 Fetch → Pull을 눌렀어. 그러자 GitHub에 있던 새 파일이 김작 컴퓨터의 Godot 프로젝트 폴더로 내려왔어.
Godot가 새 그림을 자동으로 읽고, F5를 누르자 지금 화면이 나온 거야.

채코치한 줄로 줄이면:
김작이 그림 업로드 → 채코치가 코드 수정 → GitHub에 결과 업로드 → 김작이 GitHub Desktop으로 Pull → Godot에서 F5

채코치앞으로의 기본 작업도 거의 똑같아.
김작: 여기서 원하는 작업을 말함
채코치: 코드 수정·검사·커밋·push
김작: GitHub Desktop에서 Fetch origin → Pull origin
김작: Godot에서 F5 확인

채코치즉, 예전처럼 지시문과 작업 결과를 로컬 Codex 사이에서 계속 복사할 필요가 크게 줄었어. 김작은 이제 주로 회의하고, Pull하고, F5로 확인하는 감독 역할을 하면 돼.

김작완벽하다! 굿굿굿! 한 단계 또 바이브 코팅 작업이 진화했어!

채코치ㅎㅎㅎ 맞아, 이번에 작업 파이프라인이 확실히 한 단계 진화했어! 이제 기본 루프는 정말 간단해졌어.
김작이 방향 결정 → 채코치가 직접 구현·커밋·push → GitHub Desktop에서 Pull → Godot F5 확인
앞으로 김작은 반복적인 복붙 작업보다 기획·판단·QA에 집중할 수 있어.

이 작은 배경화면 작업 하나로 새 파이프라인 전체가 실전 검증됐다. 김작은 방향을 정하고 결과를 확인하는 역할에, 반복 작업은 채코치가 GitHub를 통해 직접 처리하는 구조로 넘어간 것.

T03 — 적도 전쟁을 한다

지금까지는 플레이어가 침공하는 쪽이었다. T03은 반대로, AI가 먼저 쳐들어오고 플레이어가 방어하는 흐름을 완성하는 트랜잭션이다.

설계를 먼저 잠갔다: 침공 확률 20%, 게임 초반 3턴은 평화, 전쟁 한 번 치른 뒤엔 2턴 휴식, 적 턴 전체에서 전쟁은 최대 1회. AI끼리 붙는 전쟁도 플레이어에게 유불리 없이 공정하게 돌아가야 한다는 원칙도 세웠다. 보급은 가장 많은 자원부터 소비하다가 같은 턴에 다음 자원으로 자동 전환되고, 병과·고유기술·난수 보정은 각각 최대 ±5%로 제한했다. 자동 전투는 전투 ID 기반으로 결정론적으로 처리해서, 같은 조건이면 같은 결과가 나오게 했다. 30턴 안에 결판이 안 나면 수비 측 승리로 처리한다.

구현은 T03-A부터 T03-E까지 쪼개서 진행했고, AI 전투 결과를 먼저 정산·저장한 다음에 영상과 보고서를 보여주는 순서, 저장·불러오기 시 중복 정산 방지까지 확인한 뒤 완료했다. T02에서 만들어둔 병참·부상병·점령 규칙을 그대로 재사용해서, 새로 만든 부분보다 연결한 부분이 더 많았다.

T04–T05 — 턴을 넘기면, 통일도 온다

턴 종료 처리와 승리 조건을 하나로 묶었다. 따로 나누면 T04 끝에서 임시 종료 조건을 만들었다가 T05에서 다시 연결해야 해서 오히려 중복 작업이 생기는 구조라, 둘을 한 트랜잭션으로 처리하는 게 맞다고 판단했다.

완성된 흐름은 이렇다: 턴 종료 클릭 → 도시별 자원 생산·상태 갱신, 연구 진행·완료, 부상병 회복, AI 내정·침공 처리 → 다음 플레이어 턴 진입. 그 사이 플레이어가 한반도 4성을 전부 통일하면 승리, 영토가 0개가 되면 패배로 판정하고 결과 화면을 띄운 뒤 저장한다. T03에서 이미 AI 침공·점령·세력 멸망·통일 플래그·저장 기반을 상당 부분 만들어놨던 덕분에, 실제로는 이 흐름을 하나로 잇는 작업이었다.

T06 — 장수 시스템, 처음부터 다시 짠다

여기서부터가 이번 devlog의 진짜 핵심이다. 39명 장수의 능력치·병종·역할·고유기·기세를 전부 재설계하고, 그걸 게임에 안전하게 연결하는 작업이었다.

세 층 구조로 나누기

먼저 개념부터 정리했다. 병종은 부대의 기본 성능, 역할은 장수의 패시브 전투 성향, 고유기는 강력한 개별 능력 — 이렇게 세 층으로 나눴다.

역할 8종을 확정했다: 돌격(근접 공격 피해 +10%), 선봉(첫 교전 피해 +12%), 방어(받는 피해 -8%), 지휘(2칸 내 아군 공격·방어 +5%, 오라), 기동(측면·후방 공격 피해 +8%), 원거리(사거리 2 이상 공격 피해 +8%), 책략(상태이상·약화 효과 +12%), 지원(버프·회복·기세 회복 +12%). 역할은 고유기처럼 강해선 안 되고, 장수의 기본 성향을 만드는 소규모 보정에 머물러야 한다는 걸 원칙으로 잡았다. 예를 들어 권율은 보병·방어(받는 피해 -8%, 방어 태세 +15%)에 고유기 "행주대첩 항전", 척준경은 보병·돌격(근접 공격 +10%, 첫 공격 추가 피해)에 고유기 "검왕돌파", 이순신은 원거리·지휘(주변 아군 명중·기세 획득 보조)에 고유기 "학익진 포격" — 같은 능력치라도 역할과 고유기 조합에 따라 플레이 감각이 완전히 달라지게 설계했다.

병종은 원래 지원을 포함한 구성이었는데, 최종적으로 지원 병종을 삭제하고 궁병과 총병으로 대체했다. 최종 분포는 보병 11, 궁병 11, 기병 10, 총병 4, 궁기병 3, 총 39명 기준으로 확정했다.

지역별 평균 능력치도 검토했다. 한반도, 중국, 일본, 몽골 네 지역 각각 평균 지휘력·무력·지력·정치를 비교해서 특정 지역이 지나치게 강하거나 약하지 않은지 확인하는 과정을 거쳤다.

어떻게 게임에 넣을 것인가

밸런스 설계는 엑셀로 정리했는데, 게임이 엑셀을 직접 읽는 방식은 아니다. 왜 이렇게 가는지 나눈 대화가 있다.

김작나는 엑셀로 정리했지만 너는 엑셀을 쓰진 않잖아? 이걸 어떻게 게임에 넣을거야?

채코치맞아. 게임이 엑셀 파일을 직접 읽게 만드는 건 아니야. 엑셀은 우리가 설계를 검토하고 확정하는 사람용 원본 명세서야.
실제 게임에는 엑셀 내용을 Godot이 읽기 좋은 데이터 파일로 변환해서 넣어.

채코치실제 적용 구조는 이래.
엑셀 확정본 → (변환) → JSON 또는 Godot Resource → (로드) → 장수 데이터·병종·역할·고유기 시스템 → 전투 화면과 AI에서 사용
내 추천은 엑셀 → JSON → Godot 런타임 로드 방식이야.

채코치파일을 하나에 몰아넣지 않고 이렇게 나누는 게 좋아.
data/heroes/ — hero_base_stats.json(지휘력·무력·지력·정치, 육전·수전 배율), hero_battle_profiles.json(병종·주 역할·보조 역할·고유기 연결 ID), hero_unique_skills.json(고유기명·대상·사거리·반경·위력·지속시간)
data/battle/ — unit_type_rules.json, battle_role_rules.json, momentum_rules.json

채코치변환은 tools/import_hero_design.py 스크립트가 담당해. 엑셀 시트를 읽어서 장수 39명 hero_id 중복 검사, 병종·역할 내부값 검사, 고유기 ID 연결 검사, 사거리·반경·기세 비용 검사를 거쳐 JSON을 생성하고, 오류가 있으면 변환을 중단해.
즉 엑셀을 수정한 뒤 이 스크립트를 한 번 실행하면 게임 데이터가 자동 갱신되는 구조야.

채코치엑셀을 게임의 실시간 원본으로 직접 읽는 방식은 피하는 게 좋아. 배포 빌드에서 엑셀 라이브러리가 필요해지고, 형식 오류에 취약하고, 런타임 속도와 안정성이 떨어지고, 변경 추적과 코드 리뷰가 어려워지거든.
그래서 구조는 이렇게 확정하는 게 맞아 — 엑셀은 설계 마스터본, JSON은 게임 데이터 원본, GDScript는 데이터를 해석하고 실행하는 로직.

단계별로 안전하게 연결하기

이 구조를 실제로 연결하는 과정은 한 번에 하지 않고 잘게 쪼갰다.

  • T06-0: worldmap_main.gd 안에 39명 장수 데이터가 그대로 박혀 있던 걸 hero_definition_registry.gd라는 별도 파일로 분리. 이때는 데이터 내용을 하나도 바꾸지 않고 보관 위치만 옮기는 작업이었다 — 능력치, 이름, 소속 도시, 스킬 정보, 저장 방식, 전투 연결 방식 전부 그대로 두고 직접 참조 4곳만 새 레지스트리로 교체했다.
  • T06-1~2: 엑셀 워크북 스키마를 정하고, 게임 코드는 건드리지 않은 채로 최종 엑셀을 검사해서 39명 JSON과 검증 보고서를 자동 생성하는 변환기부터 구현했다.
  • T06-3: 기존 데이터와 새 JSON을 나란히 비교해서 완전히 일치하는지 검증한 뒤에야 Godot에 연결했다.
  • T06-4~5: 전투 진입 시점에만 새 장수 능력치·병종 프로필을 읽는 어댑터를 먼저 구현하고, 이후 실제 전투 장수 등록 함수에서 이 어댑터를 호출하도록 연결했다. 이 단계까지도 기존 공격·방어 계산은 그대로 보존했다.
  • T06 통합: 어댑터를 전투 본체에 실제로 연결해서 39명 모두 새 설계 데이터를 갖게 하고, 6병종의 이동력·사거리 기본값과 주 역할 정보를 연결했다. 지휘력·무력·지력·정치는 엑셀 최종본으로 전면 교체하고, 기존 세이브는 저장된 현재 충성도를 유지하는 반면 새 게임은 initial_loyalty에서 시작하도록 나눴다.
  • T06-6: 그동안 나뉘어 있던 과거 하드코딩 Registry, 최종 JSON, 월드맵 후처리, 전투 후처리 이 네 갈래를 HeroIdentityRegistry + HeroDesignDataRegistry → HeroRuntimeFactory라는 한 경로로 통합했다. 월드맵 첫 카드 생성부터, 전투 스폰 순간부터 최종 데이터를 쓰도록 만들고, 이동 후에야 병종이 바뀌는 것 같은 후행 갱신 경로는 전부 제거했다. 죽은 legacy 코드(hero_battle_profile_integration.gd)도 이 과정에서 삭제했다.
  • T06-6B-hotfix1: 월드맵 Context가 슬롯 장수를 바꿀 때 이름·초상화만 덮어쓰던 방식을 없애고, hero_id가 바뀌면 병종·사거리·역할·이미지까지 Factory에서 전부 다시 만들도록 고쳤다. 이 수정 덕분에 적군도 광개토대왕은 기병, 을지문덕과 도림은 궁병, 척준경은 보병으로 처음부터 정확하게 생성된다.
  • T06-7: 진영별 공용 기세 시스템을 완성했다. 시작값 3, 최대 10, 라운드 완료 시 +1, 공격 성공 시 공격 측 +1, 피격 시 피해 측 -1. 장수별 고유기 기세 비용은 1~4로 차등을 두고, 선택 취소나 대상 검증 실패 시엔 기세를 차감하지 않으며, 실행이 확정된 뒤 회피나 면역이 발생해도 환불은 없다. 39명 고유기를 공통 Resolver 하나로 실행하게 만들고, 플레이어 UI에 기세를 표시하고 AI도 기세를 보존하며 고유기 사용을 판단하도록 연결했다.
  • T06-8: 39명 고유기 각각을 전수 감사했다. 이순신 학익진(광역 피해+명중 저하+이동 저하), 권율·계백(피해 감소+반격 보정), 척준경(처치 시 1칸 전진), 을지문덕(이동력 -2+진형 붕괴), 의자왕(범위 내 최저 HP 적 1명 행동 지연), 제갈량(적 이동·명중 저하와 아군 방어 상승 동시 적용), 여포(첫 피해 50% 추가 피해 1회), 노부나가(방어 보정 무시) 등 — 설계값과 실제 계산이 어긋나는 항목을 찾아 같은 트랜잭션 안에서 수정·검증까지 끝냈다.
  • T06-9: 월드맵-편성-전투-저장 전 구간에서 같은 장수가 화면마다 다른 값으로 보이지 않도록 데이터 흐름 전체를 하나의 계약으로 잠갔다. 전투 결과에 진영별 장수 개별 결과(생존 여부, 현재/최대 HP, 병력, 병종, 고유기 ID)를 추가하고, 전투에서 쓰러진 장수가 소속 도시 없이 붕 떠버리는 문제도 이때 잡았다.

최종 밸런스 확정

이 모든 재설계 끝에 나온 39명 장수의 최종 스탯표다.

한반도 이순신(지휘 99·무력 88·지력 96·정치 78, 궁병), 정도전(지력 97·정치 99, 궁병), 권율(무력 86·초기충성도 97, 보병), 척준경(무력 100·초기충성도 82, 기병) — 이런 식으로 지역별 대표 장수들의 밸런스가 한 화면에 다 들어왔다.

재설계가 끝난 장수들 중 몇몇은 이미 컷인 초안까지 나왔다. 아래는 척준경, 의자왕, 김유신, 김춘추 네 장수의 컷인이다.
