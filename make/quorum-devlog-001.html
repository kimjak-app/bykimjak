쿼럼 제작일지

여러 AI의 의견을 연결하고, 내가 판단하고 실행하는 작업 도구.

QUORUM · MAKING LOG #001

네 명의 AI 코치를 한자리에, 쿼럼을 만들다

EASTWAR의 3D 전장과 에셋 제작을 위해 시작한 AI 오케스트레이션

2026.10.27 · 첫 제작 기록

여러 AI와 함께 일하면서 꼭 해보고 싶었던 일이 있었다. 각자에게 질문하고 답을 받는 데서 한 걸음 더 나아가, 서로 다른 의견을 연결하고 내가 원하는 작업으로 이어가는 것. 내가 생각하는 AI 오케스트레이션은 그렇게 시작한다.

EASTWAR를 개발하면서 그 필요가 더 구체적이 됐다. 지금은 기존 전투를 3D 전장으로 옮기고, 그 안에 들어갈 나무와 바위, 산맥과 성 같은 에셋을 설계하고 구현하는 중이다. 외형이 좋아도 부대를 가리면 곤란하고, 지형이 멋져도 실제로 이동할 수 있는 칸과 맞지 않으면 문제가 생긴다. 한 가지 제안을 여러 관점에서 검토하고, 선택한 방향을 구현하는 도구에 정확히 전달할 필요가 있었다.

쿼럼은 이 작업을 더 빠르고 효과적으로 해보기 위해 만들었다. 아직 기초적인 단계지만, 오래 생각해온 오케스트레이션을 내가 하는 실제 작업에 적용해보는 첫 시도다.

창을 오가던 시간을 한 화면으로

ChatGPT에 물은 내용을 Claude에도 보내고, Grok의 제안을 다시 다른 AI에게 보여주고, Gemini의 의견도 비교했다. 같은 질문과 이미지를 여러 창에 반복해서 붙여 넣다 보면, 정작 검토할 내용보다 전달하는 일에 손이 많이 갔다.

오늘은 그 과정을 위한 Windows 앱을 코덱스와 함께 만들었다. 이름은 쿼럼, QUORUM이다. ChatGPT·Claude·Grok·Gemini의 웹 화면을 최대 네 개까지 한 창에 열고, 공통 질문을 작성한 뒤 답을 받을 AI를 선택하는 방식이다. 모두에게 보낼 수도 있고, 특정 AI에게만 보낼 수도 있다.

답변은 내가 직접 읽고 비교한다. 다른 AI의 검토가 필요한 의견은 복사해 ‘의견 공유함’에 넣고, 누구의 의견인지와 무엇을 검토할지 적어 전달한다. 방향이 정리되면 ‘최종 정리’의 내용을 복사해 Claude Code 같은 실제 작업 도구에 넘긴다.

화면은 두 개, 세 개, 네 개로 나눠 쓸 수 있고, 하나를 크게 봤다가 다시 돌아올 수도 있다. 작업 상태를 저장하고 복원하는 기능, 실패한 대상만 다시 시도하는 기능도 넣었다. 내가 하던 협업 방식을 한 화면에서 다루도록 만든 셈이다.

내가 중심에 있는 오케스트레이션

쿼럼이 AI의 답변을 자동으로 모으거나, AI끼리 토론시켜 최종 결론을 내주지는 않는다. 현재의 질문, 의견 공유, 최종 판단은 모두 내가 주도한다. 어떤 의견을 다른 AI에게 보여줄지, 어느 부분을 받아들이고 무엇을 다시 물을지도 내가 결정한다.

EASTWAR의 나무 하나를 만들 때도 같은 원칙이 적용된다. 외형에 대한 의견과 게임 안에서의 크기, 부대 가림, 성능에 관한 의견을 함께 놓고 본다. 그리고 지금 프로젝트에 맞는 방향을 골라 실제 구현으로 넘기려 한다. 쿼럼은 이 과정을 연결하는 작업대다. 얼마나 시간을 줄이고 결과를 개선하는지는 앞으로 계속 사용하며 확인할 일이다.

코덱스와 구현한 첫 구조

앱은 C#과 Windows Forms, .NET Framework 4.8을 바탕으로 만들었다. 네 개의 AI 화면에는 Microsoft Edge WebView2를 사용한다. 화면마다 별도 프로필을 두어 로그인 환경을 나누고, 각 서비스에는 사용자가 직접 로그인한다. 현재는 API 키를 연결하는 방식이 아니며, 각 계정의 구독과 이용 제한은 그대로 적용된다.

공통 질문을 보내면 서비스별 JavaScript 어댑터가 입력칸과 전송 버튼을 찾아 처리한다. 선택한 대상은 병렬로 처리하고, 결과는 AI별로 표시한다. 이미 작성한 초안을 덮어쓰지 않거나, 전송 버튼이 불분명하면 멈추는 등 잘못 보내는 상황을 줄이기 위한 처리도 넣었다.

파일 첨부는 원본 대신 임시 복사본을 사용한다. 웹 화면의 파일 입력을 통해 전달하고, 최신 beta.2에서는 ChatGPT와 Claude의 이미지 붙여넣기 대체 경로를 보완했다. 첨부 표시와 업로드 상태를 확인한 뒤 질문을 보내도록 했지만, 실제 사이트마다 표시 방식이 달라 계속 확인이 필요한 부분이다.

사용을 시작했지만, 검증은 계속된다

기본 쿼럼은 이미 실제 작업에 사용하고 있다. 다만 이미지와 파일 첨부까지 모든 서비스에서 안정적으로 작동한다고 말할 단계는 아니다. 개발 보고서 기준으로 최신 자체 시험에는 17개 PASS가 기록되어 있다. 한글과 여러 줄 입력, 초안 보호, 중복 방지, 화면 구성과 저장, 첨부 실패와 재시도 등을 로컬 시험 환경에서 점검한 결과다. 이 시험에서 외부 AI에 실제 메시지를 보내지는 않았다.

실제 서비스 시험에서는 Grok과 Gemini에 이미지가 도착한 것을 봤지만, 앱이 첨부 완료를 확인하지 못한 경우가 있었다. ChatGPT와 Claude의 첫 첨부 시험은 입력 영역을 찾는 과정에서 실패했고, 이를 보완한 beta.2의 실제 서비스 재시험 결과는 아직 확인 중이다.

또 ‘전송 요청됨’은 전송 버튼을 클릭했다는 뜻이다. 서버가 실제 메시지를 받아 처리했는지까지 확정한 표시는 아니다. 사이트 화면이 바뀔 때의 대응, 파일 종류와 용량 제한, 첨부 완료 판정과 전송 확인을 더 다듬어야 한다.

오늘 만든 것은 완성된 자동 협업 시스템이 아니다. 내가 꼭 해보고 싶었던 오케스트레이션을 EASTWAR의 3D 전장과 에셋 제작에 쓰기 위해 마련한 첫 도구다. 이제는 이 도구로 실제 작업을 이어가며, 필요한 기능과 불편한 부분을 하나씩 찾아가려 한다.
