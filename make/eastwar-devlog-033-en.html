Dev Log · #033

The Last Pieces of the Battle HUD

The Supply Panel, Center Info HUD, and a First Complete Layout

August 14, 2026

Measuring the Width Before the Numbers Break

With the roster, momentum bar, and battle log panel all in place, next up was the battlefield supply panel. This stage wasn't about wiring in real functionality — it was purely "layout practice for design." The actual world-map-to-battle runtime supply data handler, T02BattleSupplyPanel, stayed untouched; a fully separate, test-only mock HUD got built instead.

Labels came first. Each row follows an [icon] + item name + number format, kept to short fixed labels — Food, Salt, Consumption, Duration — instead of longer phrasing like "consumption per turn" or "turns sustainable."

The real substance came next: designing the layout width around the maximum possible digit count, not the numbers currently on screen. The standard set: Food and Salt up to 99999 (5 digits), Consumption up to 9999 (4 digits), Duration up to 999 turns (3 digits + "turns") — all without breaking the layout. If the width were sized to match today's 3-digit numbers, the layout would collapse the moment the game grows and those numbers get bigger. So the structure was built to let QA actually plug in these maximum values and verify against them.

The Same Rule for the Enemy Side

The "highlight the currently acting general" rule that already existed on the ally roster got applied identically to the enemy side. Only the card of the currently acting enemy general gets highlighted, with a roughly 2px gold border and a soft tan/gold-brown background tint, while text, portrait, and unit-type info stay unchanged. A strong pure-red glow got ruled out — trying to make it look threatening risked making the screen look messy instead.

The Skeleton of the Center-Bottom Info Panel

Next came the "currently acting general" info panel meant for the bottom center of the screen. Layout came first:

  • Portrait — a large square
  • General info — name, unit-type square + label, troops/wounded, Leadership/Martial/Intelligence icons + numbers, unique skill square + name + short effect description
  • Status info — icon + effect name + remaining turns shown fully across multiple lines, with hover for a detailed description
  • Terrain — a square for terrain art, terrain name, terrain effects to come later

The "portrait" here is a different spec from the small face crops used in the roster. Roster portraits are small squares sitting inside a card, but the center panel's portrait takes up a large vertical space at the bottom of the screen — it needed a separate art asset with real expression and armor detail visible.

Vertical portraits for the center info panel — Kim Yu-sin, Guan Yu, Xiahou Dun, Zhang Fei

Icons for each stat got built alongside this. Martial got a sword, Intelligence got a book, Unique Skill got a scroll etched with a dragon, and Terrain (Plain) got a circular emblem depicting mountains and fields.

Once the layout was set, real data got wired in. Name, portrait, unit type, troops (current/max), Leadership, Martial, Intelligence, unique skill, status, and terrain each got connected to their actual data source — nothing got faked in for missing values. Wounded troop counts stayed hidden for now, with troops shown as current/max only.

Final Polish

The vertical portrait got connected to the info panel, with a "Ready" flag added to the bottom-right corner of the portrait to indicate whether the unique skill is available. The center info panel got enlarged relative to the status panel, and the unique skill description got stabilized to consistently render across 2 lines. Status icon slots got fixed in place so the layout wouldn't shift when there's no value to show.

A few small cleanups happened along the way. A local variable named ready had been shadowing the Node's own ready signal, triggering a warning — renamed to skill_ready to clear it. stretch_mode got explicitly cast to TextureRect.StretchMode to clear an enum-related warning (confirmed via Godot's official docs that stretch_mode is indeed a StretchMode enum property). Visually, only the icon in front of the status section's title got kept, while the square icons in front of individual status rows (attack/defense boost, damage reduction, counter enhancement, etc.) got hidden below it. Ally cards that had finished acting no longer looked fully dead and blacked out — the existing Ready frame got reused as a thin blue-gray "completed" frame instead, with that treatment blocked from triggering while an attack animation is playing.

The Finished Screen

At this point, all the pieces making up the battle screen — roster, momentum bar, battlefield supply, battle log, and center info panel — finally sat together on one screen.

The ally roster shows Yi Sun-sin, Jeong Do-jeon, Gwon Yul, Kim Yu-sin, and Eulji Mundeok; the enemy roster shows Guan Yu, Zhang Fei, Xiahou Dun, Liu Bei, and Zhuge Liang. The center info panel is locked onto Yi Sun-sin, the currently acting general, with the Crane Wing Formation skill description and the "Plain" terrain indicator both visible in the same frame.

From "not even one HUD is working" on a Saturday night to now — roster frame, banners, battle log, battlefield supply, and the center info panel — nearly every piece that makes up the battle screen has fallen into place.

What's Next

What's left is wiring this finished layout into actual battle events — skills, status effects, combo attacks — and filling in the pieces still marked "later," like terrain effects.
