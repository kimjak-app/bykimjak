EASTWAR 개발일지 #025

문서가 코드보다 무거워졌을 때 — MVP 디테일 작업 전, MD 구조부터 정리하다

2026년 7월 16일

문서가 문서를 반복하고 있었다

MVP 디테일 작업에 들어가기 전에, 먼저 짚고 넘어가야 할 게 있었다. agent 문서들 상태를 다시 들여다봤더니, 예상보다 심각했다.

CURRENT_STATE.md, NEXT_TASKS.md, HANDOFF_TO_CODEX.md — 이 세 문서가 전부 과거 버전을 계속 누적하고 있었다. v0.72-04, v0.72-03, v0.72-02, v0.72-01, v0.71 전체 이력이 CURRENT_STATE.md 안에 그대로 남아 있었고, 같은 작업 기록이 세 문서에 나눠서 반복 기록되고 있었다.

더 문제였던 건 NEXT_TASKS.md였다. 이름은 "다음 할 일"인데, 실제로는 이미 끝난 v0.72 작업들이 계속 "Current" 항목으로 남아 있었다. 사실상 두 번째 CHANGELOG가 되어 있었던 셈이다. HANDOFF_TO_CODEX.md도 마찬가지로, 오래전에 끝난 v0.71·v0.72 인수인계 내용을 계속 안고 있어서 최신 지시를 찾으려면 지나간 내용을 전부 통과해야 하는 구조였다.

지금까지의 초세분화 방식 — 작업 하나마다 계획서·감사·QA·Complete Lock 문서를 따로 만드는 방식 — 은 월드맵/전투 리팩토링처럼 안전이 최우선인 작업에선 잘 맞았다. 하지만 앞으로 MVP 디테일 작업, 즉 트랜잭션 단위로 움직이는 개발 방식에서는 오히려 이 구조 자체가 컨텍스트 비용을 키우는 원인이 된다.

판단: 삭제가 아니라 압축

가장 먼저 정한 원칙은 이거였다. 문서를 지우는 게 아니라, 문서가 하는 일을 줄인다. 과거 기록은 Git에 이미 다 남아 있으니, 지우는 대신 archive로 옮기고 현재 컨텍스트에서만 빼는 방식으로 가기로 했다.

유지할 문서, 구조 바꿀 문서, 새로 만들 문서

그대로 유지: WORKFLOW_MANAGER.md(최상위 안전 계약), GODOT_RULES.md(씬/UID/리소스 규칙, 단 문서-only 작업에선 생략 가능), BATTLE_WORLDMAP_HANDOFF_CONTRACT.md(월드맵-전투 경계 계약, 여기에 공격/방어 공통 입력 계약·중복 적용 방지 토큰 등을 추가)

역할은 유지하되 좁힐 것: CODEX_WORKFLOW_RULES.md — WORKFLOW_MANAGER.md와 겹치는 권한 헤더·커밋 정책은 통합하고, 작업 분류만 SIMPLE/MEDIUM/COMPLEX PATCH에서 PATCH/TRANSACTION/ARCHITECTURE MIGRATION으로 바꾼다

구조를 완전히 갈아엎을 것:

  • CURRENT_STATE.md → 90% 이상을 archive로 보내고 100줄 이내로 압축 (Baseline / Active Phase / Working Runtime / Implemented / Known Gaps / Active Transaction / Next Transaction / Protected Contracts만 남김)
  • NEXT_TASKS.md → 폐기하고 TRANSACTION_ROADMAP.md로 교체 (Active / Next / Later / Blocked, 완료된 건 즉시 제거)
  • HANDOFF_TO_CODEX.md → 별도 문서로 계속 누적하는 대신, 트랜잭션 문서 안에 Execution Brief 섹션으로 흡수. 굳이 파일이 필요하면 매번 덮어쓰기만 한다

통합할 것: ARCHITECT_AGENT.md, IMPLEMENTATION_AGENT.md, QA_AGENT.md, RUNTIME_QA_AGENT.md, VISUAL_QA_AGENT.md — 다섯 개를 DEVELOPMENT_ROLES_AND_QA.md 하나로 합치고, 기본 읽기 목록에서 빼서 필요할 때만 조건부로 읽는다

새로 만들 것: MVP_MASTER_PLAN.md(한반도 4성 MVP 전체를 정의하는 최상위 문서), TRANSACTION_DEVELOPMENT_RULES.md(트랜잭션 단위 작업 방식 정의), TECH_TREE_GAMEPLAY_CONTRACT.md(테크트리를 실제 게임에 연결하는 계약), KOREA_MVP_SCENARIO.md(활성 성·세력·장수·승패 조건), SYSTEM_SOURCE_OF_TRUTH.md(같은 데이터를 누가 관리하는지 명시)

archive로 이동: 버전별 리팩토링 계획서, 과거 QA 문서, Complete Lock 문서, 이미 상위 문서에 반영된 감사 자료 — 전부 agent/archive/v0_70/, v0_71_refactor/, v0_72_battle_refactor/, qa/, superseded_designs/ 폴더로

앞으로 지킬 규칙

  • 1. 현재 문서는 짧게 유지한다 — CURRENT_STATE.md 100줄 이내, TRANSACTION_ROADMAP.md 50줄 이내
  • 2. 같은 사실을 여러 문서에 복사하지 않는다 — 최신 커밋은 CURRENT_STATE.md 한 곳에만, 나머지는 참조만
  • 3. 완료된 트랜잭션은 즉시 archive로 — CURRENT_STATE와 ROADMAP에서는 제거하고, 핵심 결정만 계약 문서에 반영
  • 4. CHANGELOG는 Git 로그로 대체한다 — 별도 문서가 필요하면 사용자에게 의미 있는 릴리스만 기록 (helper 추출 같은 내부 변경은 제외)
  • 5. QA 문서를 별도로 만들지 않는다 — 트랜잭션 문서 안의 Acceptance Tests / Completion Result에 기록. 전체 회귀·출시 후보처럼 정말 독립 가치가 있을 때만 예외
  • 6. Complete Lock 문서를 남발하지 않는다 — 잠가야 할 경계는 계약 문서 안에 "Protected Contract" 섹션으로
  • 7. 매 세션 전체 문서를 읽지 않는다 — 기본 5개(WORKFLOW_MANAGER, DEVELOPMENT_RULES, MVP_MASTER_PLAN, CURRENT_STATE, ACTIVE_TRANSACTION)만 읽고, 나머지는 작업 성격에 따라 조건부로

agent/
├─ WORKFLOW_MANAGER.md
├─ DEVELOPMENT_RULES.md
├─ GODOT_RULES.md
├─ MVP_MASTER_PLAN.md
├─ CURRENT_STATE.md
├─ TRANSACTION_ROADMAP.md
├─ contracts/
│  ├─ SYSTEM_SOURCE_OF_TRUTH.md
│  ├─ WORLDMAP_RULES.md
│  ├─ BATTLE_WORLDMAP_HANDOFF_CONTRACT.md
│  └─ TECH_TREE_GAMEPLAY_CONTRACT.md
├─ scenarios/
│  └─ KOREA_MVP_SCENARIO.md
├─ transactions/

└─ archive/
   ├─ v0_70/
   ├─ v0_71/
   ├─ v0_72/
   ├─ old_qa/
   └─ superseded/

이렇게 정리하면 새 세션 시작할 때 읽는 양이 지금의 20~30% 수준으로 줄어든다. 안전 계약은 그대로 다 남기면서, 정작 매번 다시 읽을 필요 없는 건 걷어내는 것. 이게 되어야 다음 단계 — 한반도 4성 MVP 트랜잭션 작업 — 을 시작할 수 있다.
