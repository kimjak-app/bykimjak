EASTWAR Devlog #014

Same Screen, A Completely Different Game Underneath

May 23, 2026

What Actually Changed These Three Days

These three days looked uneventful from the outside — still the same 2v2 battles, same arrows flying from the same spots. But underneath, the entire skeleton got swapped out.

One Slot at a Time

Until now, ally main, ally support, enemy main, and enemy support were each managed as separate fixed variables. That worked fine for 2v2, but it was never going to scale to 5 or 7 units.

So I migrated each slot into the new structure one at a time — ally main first, watch for two days, then ally support, and so on. Moving slowly turned out to be the safest way to avoid breaking anything.

  • Migrated in order: ally main → ally support → enemy main → enemy support
  • The only rule: battle outcomes had to stay identical before and after
  • Click areas and facing indicators stayed linked by reference, not physically moved

How Reinforcements Arrive

The real goal this round: instead of all 5 units starting the fight together, reinforcements now arrive mid-battle — and with a structure that can later carry "dispatched from a neighboring city" as an actual story, once the world map exists.

Each reinforcement now carries metadata about which city it came from and why. It also triggers a short "Reinforcements Arrived!" toast the moment it enters. Getting that toast to not collide with the existing round-transition toast took a bit of a queueing fix.

Making Sure Yi Sun-sin and Gwon Yul Never Get Mixed Up

As the roster grew, hero portraits and unit identities started swapping — Yi Sun-sin's slot showing Gwon Yul's face, Guan Yu and Xiahou Dun crossing wires. With only 2 heroes it never showed; with 5, it broke immediately.

So I built a single source of truth: one rule deciding which hero belongs to which slot, referenced by name, portrait, click handling, and the info panel alike.

Closing In On the Last Surviving Unit

Running auto-battle repeatedly turned up something odd: with only one ally unit left, five enemy units would surround it — and just stand there. Overwhelming numbers, and nobody threw the final blow.

The enemy AI turned out to be too conservative about "not needing to rush." So the logic changed: enemies now always seek an engageable position, closing in harder as the ally count shrinks, flanking around if the front is blocked.

It's not perfect yet — a unit or two still hangs back sometimes. That's next on the list.

What's Next

These three days built the skeleton for true 5v5 battles. Next up: the command panel that appears on unit click, and tightening the one-click move interaction.
