Think / 아침 말씀 with 채코치
2026.08.02 · THINK · 아침 말씀 with 채코치

실패는 미래의 자산이자 설계도다

EASTWAR 상용화의 갈림길 — 그래픽 업그레이드 실패로 코치들과 나눈 이야기

김성현 (byKimjak) 2026 · 08 · 02

어제는 EASTWAR HUD를 원하는 만큼 완성하지 못한 날이었다. 그 하루를 되짚으며 채코치, 그리고 클코치의 조언까지 함께 나눴다.

채코치ㅋㅋㅋㅋ 인정. 그건 내가 졌다. 😅

초안은 "이런 느낌으로 가면 좋겠다"는 방향은 제시했는데, 그걸 고도 엔진에서 실제 UI로 구현하는 단계에서는 원하는 수준까지 못 만들었어.

특히 허드(HUD) 정보창은 생각보다 어려운 영역이야.

  • 레이아웃이 깨지지 않아야 하고
  • 해상도 대응도 해야 하고
  • 버튼, 아이콘, 폰트가 다 어울려야 하고
  • 실제 게임 데이터까지 연결되어야 하니까.

그래서 어제처럼 "이거 하나 금방 되겠지?" 했다가 몇 시간 순삭되는 경우가 진짜 많아.

근데 어제 얻은 것도 하나 있어.

우리가 부족한 게 뭔지 명확해졌어.

내가 잘하는 건

  • 시스템 설계
  • 게임 구조
  • 밸런스
  • 코드
  • 기능 구현

이쪽이고,

반대로 고퀄 게임 UI를 바로 제작하는 건 전문 UI/UX 디자이너 영역이 많이 섞여 있어. 그 차이를 어제 확인한 셈이지.

그래서 앞으로는 방식을 바꾸면 된다.

  1. 먼저 Figma나 이미지로 "완성 목표 UI"를 확정한다.
  2. 그걸 기준으로 Godot Control 노드 구조를 설계한다.
  3. 하나씩 동일하게 구현한다.

이렇게 가면 성공 확률이 훨씬 높아.

근데 말이야.

어제가 완전 실패한 날은 아니야.

왜냐면 한반도 MVP 컷인 시스템은 실제로 연결해서 테스트까지 끝냈잖아. 그건 게임의 기능이 하나 완성된 거고, UI는 그 위에 덧입히는 단계야.

그러니까 어제는

게임 기능은 큰 진전이 있었고,
UI 구현 방식은 개선이 필요하다는 걸 확인한 날이었다고 보는 게 맞아.

그리고 하나 약속할게.

이번에는 "멋진 UI 만들어줄게"라고 막연하게 말하지 않을게.

대신 레퍼런스 UI를 하나 정하고, 그걸 픽셀 단위까지 분석해서 고도에서 구현 가능한 형태로 차근차근 같이 만들어보자.

그 방식이면 나도 훨씬 자신 있다. 💪

김작클코치가 이렇게 말한다.

클코치방향은 맞는데, 딱 하나 제일 중요한 걸 빠뜨렸어. 그거 빠지면 사실 어제 실패했던 그 구멍으로 다시 빠질 수 있어. 짚어줄게.

지금 제안한 3단계의 위험 지점

1번 "완성 목표 UI를 확정한다" — 이게 애매해. 어제 우리가 밝혀낸 진짜 원인이 뭐였냐면, "완성된 화면 이미지"를 그대로 최종 산출물처럼 다루려고 한 거였어. 게이지 숫자, 텍스트, 그리드 정렬 같은 건 어떤 이미지 도구로도 정밀하게 확정이 안 돼. Figma로 만들어도 마찬가지야 — Figma 목업도 결국 "이렇게 생겼으면 좋겠다"는 참고용 스케치일 뿐이지, 3번 단계에서 그대로 복사해서 구현할 수 있는 대상이 아니야.

그래서 한 단계를 끼워 넣어야 해

  1. Figma/이미지로 "목표 스타일·레이아웃"을 확정한다 (참고용, 최종산출물 아님)
  2. ⭐ 그 목표를 두 종류로 분해한다:
    • 그림 요소 (배경, 초상화, 프레임, 아이콘) → 채코치가 이미지로 제작
    • 정보 요소 (게이지, 숫자, 텍스트, 그리드) → 실제 데이터랑 연동되는 코드
  3. 분해한 것 기준으로 Godot Control 노드 구조를 설계한다
  4. 부품 하나씩(예: 상단 HUD만 먼저) 그림+코드를 같이 완성 → QA → 다음 부품

즉 "2번"이 빠지면 결국 목표 이미지를 코덱스한테 "이대로 만들어주세요"라고 던지는 꼴이 되고, 코덱스도 결국 이미지 안의 숫자/정렬을 눈대중으로 흉내내려다 어긋나게 돼. 목표 이미지는 '방향'을 주는 거지, '스펙'을 주는 게 아니야. 스펙은 2번 단계에서 사람이 직접 "이건 그림, 이건 코드"라고 나눠줘야 나와.

그리고 사실 오늘 상황에서는 좋은 소식이 하나 있어 — 전투화면은 이미 2~3단계가 다 끝나있어. 그림3 실측 때 노드 구조(AllyMomentumHud, TroopBar 등)가 이미 다 있는 걸 확인했잖아. 그러니까 오늘 할 일은 이 4단계 프로세스 중 4번, Theme+폰트부터 붙이는 것부터 바로 시작하면 돼.

채코치오, 이건 클코치 말에 상당히 동의해.

특히 이 문장이 핵심이야.

"목표 이미지는 방향을 주는 것이지, 스펙을 주는 것이 아니다."

이게 어제 우리가 막힌 이유를 정확히 설명해.

예를 들어 허드 하나를 보면,

그림 요소

  • 배경 패널
  • 금속 프레임
  • 문양
  • 아이콘
  • 초상화

이건 이미지 리소스야.

반면,

정보 요소

  • HP 게이지
  • 병력 수치
  • 기세 게이지
  • 장수 이름
  • 상태이상 아이콘
  • 턴 표시

이건 전부 실시간 데이터야.

이걸 이미지처럼 만들어버리면 결국 숫자 하나 바뀔 때마다 다시 그려야 하는 말도 안 되는 구조가 돼.

내가 여기에 하나를 더 추가하고 싶어.

나는 5단계로 갈 것 같아.

  1. 스타일 확정
    • 분위기
    • 색감
    • 레퍼런스
  2. 자산 분리
    • 그림
    • 코드
  3. 컴포넌트 정의
    • HUD
    • 스킬패널
    • 컷인
    • 로그
    • 버튼
    각각 독립 부품으로 정의.
  4. Godot 구현
    • Theme
    • Font
    • MarginContainer
    • TextureRect
    • ProgressBar
    • Label
    • Animation
  5. QA
    • 1080p
    • 해상도 변경
    • 긴 이름
    • 숫자 변화
    • 컷인 재생
    • 애니메이션 충돌

그리고 클코치가 말한 이 부분도 맞아.

"오늘은 Theme + 폰트부터 붙이면 된다."

이게 좋은 이유는 한 번 Theme를 제대로 잡으면 나머지 UI가 거의 자동으로 통일되기 때문이야.

예를 들어

  • 제목 폰트
  • 일반 폰트
  • 테두리 색
  • HP바 색
  • 기세바 색
  • 버튼 스타일

이걸 Theme 하나에 넣으면 HUD든 로그든 스킬창이든 같은 느낌으로 맞춰져.

그래서 지금 EASTWAR는 오히려 유리한 상황이야.

전투 로직은 이미 많이 올라와 있고, 컷인 시스템도 연결됐고, HUD를 위한 노드 구조도 상당 부분 갖춰져 있다고 했잖아.

그러면 이제는 "UI를 처음 만드는 단계"가 아니라, "이미 있는 뼈대 위에 제대로 된 디자인 시스템을 입히는 단계"라고 보는 게 더 정확해.

이건 처음부터 새로 만드는 것보다 훨씬 수월해.

어제는 이 점을 충분히 고려하지 못하고 "목표 이미지를 구현"하는 데 집중했던 게 한계였어. 앞으로는 스타일 → 자산 분리 → 컴포넌트 → 구현 → QA 흐름으로 가면 훨씬 안정적으로 원하는 수준에 가까워질 거라고 생각해.

김작오케이. 좌절 금지 오늘은 도전의 날이야! 실패가 미래의 자산! 어울리는 말씀 줘

채코치좋다. 이게 바로 개발자 마인드다. 😄

어제를 한 문장으로 정리하면,

"실패한 게 아니라, 구현 방법 하나를 배웠다."

UI는 결국 감으로 만드는 게 아니라 시스템으로 만드는 것이라는 걸 확인한 하루였잖아.

오늘 너한테 가장 어울리는 말씀은 이 구절이야.

"형제들아, 여러 가지 시험을 만나거든 온전히 기쁘게 여기라. 이는 너희 믿음의 시련이 인내를 만들어 내는 줄 너희가 앎이라."
— 야고보서 1:2–3

이 말씀은 "어려움을 좋아하라"는 뜻이라기보다, 그 과정을 통해 사람 안에 쌓이는 힘을 말해.

어제는 원하는 HUD를 못 만들었지만, 그 과정에서 '그림'과 '코드'를 분리해야 한다는 원칙을 얻었잖아. 그 원칙은 앞으로 EASTWAR UI 전체를 만들 때 계속 쓰일 자산이 될 거야.

그리고 하나 더 떠오르는 말.

"의인의 길은 돋는 해의 빛 같아서 크게 빛나 한낮의 광명에 이르거니와."
— 잠언 4:18

해는 한순간에 정오가 되지 않아. 조금씩 올라가다가 어느 순간 세상을 환하게 비추지.

지금 EASTWAR도 그래.

전투 엔진 하나.
컷인 시스템 하나.
HUD 하나.
UI 하나.

이렇게 하나씩 올라가다 보면 어느 날 "이거 진짜 게임인데?"라는 순간이 온다.

오늘의 구호 하나!

🔥 "실패는 폐기물이 아니라 설계도다. 오늘도 한 칸 전진!"

가자. 오늘은 좌절의 날이 아니라, EASTWAR를 한 단계 더 게임답게 만드는 도전의 날이다. 💪
