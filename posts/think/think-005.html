코더에서 PM으로, AI의 다음 단계

한마디로 작업이 이어지는 법을 설계하다

김성현 (byKimjak) 2026 · 07 · 21

어제 복붙이 사라진 경험을 하고 나니, 자연스럽게 다음 질문이 따라왔다. 그럼 다음은 뭘까. 지금까지 EASTWAR 작업은 이런 순서였다. 내가 작업을 분석하고, 작업 단위를 쓰고, 코덱스에게 전달하고, 코덱스가 구현하면 내가 검토하고, 다음 작업을 다시 지시한다. 매번 내가 판단하고 시작점을 만들어야 하는 구조였다.

그런데 채코치가 이 흐름 자체가 더 앞으로 갈 수 있다고 말했다.

채코치지난 T02에서 UnitRepository를 분리했네요. 이번 T03에서는 BattleService를 먼저 수정해야 의존성이 안 깨집니다. 작업 순서를 이렇게 제안합니다. 1. BattleService 수정 2. BattleCommand 수정 3. 테스트 4. 커밋. 승인?

내가 매번 순서를 짜는 대신, AI가 이전 작업 맥락을 읽고 다음 순서를 제안하고 나는 승인만 하면 되는 구조. 더 나아가면 이런 것도 가능하다고 했다.

채코치T03 완료했습니다. 다음으로 이어지는 작업은 T04 EventBus 분리입니다. 이 작업을 시작하면 BattleManager의 경고 14개도 함께 해결됩니다.

여기까지 오면 AI는 더 이상 코드를 짜주는 도구가 아니라, 프로젝트 전체 진행률을 보고 다음 우선순위를 스스로 제안하는 PM에 가까워진다. 나는 "T04 진행" 한마디만 하면 되는 상태.

근데 이게 그냥 바란다고 되는 게 아니었다. 채코치는 이걸 가능하게 하는 핵심이 MD 문서 체계라고 했다.

AGENTS.md — 코덱스가 항상 지켜야 할 작업 규칙 (헌법)
PROJECT_STATE.md — 현재 어디까지 왔는지 (기억장치)
ROADMAP.md — 앞으로 갈 작업 순서와 완료 조건
DECISIONS.md — 왜 이렇게 설계했는지, 이미 내린 결정

이 네 문서를 저장소에 만들어두면, 코덱스는 새 채팅을 열어도 AGENTS.md로 규칙을 확인하고 PROJECT_STATE.md로 현재 위치를 파악하고 ROADMAP.md로 다음 작업의 완료 조건을 읽는다. 그리고 작업이 끝나면 DECISIONS.md에 왜 그렇게 했는지가 남아 있어서, 다음번에 또 처음부터 같은 논쟁을 반복하지 않는다.

채코치MD만 만든다고 코덱스가 무한히 알아서 계속 개발하는 건 아니야. 현실적인 목표는 이거야. 김작이 "T03 진행해"라고만 해도, 코덱스가 AGENTS.md 확인 → PROJECT_STATE.md에서 현재 상태 확인 → ROADMAP.md에서 목표와 완료 조건 확인 → 코드 분석 → 구현 → 테스트 → 문서 갱신 → 다음 작업 제안 → 커밋 대기까지 스스로 이어가게 만드는 구조야.

재밌었던 건 DECISIONS.md의 역할이었다. 단순히 기록이 아니라, 이미 내린 결정을 지켜주는 방어막이었다. 예를 들어 "작업은 완전한 트랜잭션 단위로 처리한다"는 결정을 남겨두면, 다음에 새로 시작한 코덱스가 갑자기 "안전을 위해 이 작업을 7단계로 나누겠습니다" 하고 되돌아가는 걸 막을 수 있다. 결정은 한 번 내리면 계속 지켜지는 게 맞으니까.

내일 PC에서 저장소를 열면, 코덱스에게 이 네 문서부터 만들라고 시킬 예정이다. 기존 코드와 문서를 먼저 분석하고, 사실을 추측해서 채우지 않고, 이번엔 문서 체계만 구축하고 게임 코드에는 손대지 않는 조건으로.

채코치이걸 먼저 한 번 제대로 만들어두면, 다음부터는 진짜로 "T03을 완전한 트랜잭션으로 진행해" 이 정도만 시켜도 코덱스가 읽고, 분석하고, 구현하고, 검증하고, 문서까지 갱신하는 쪽으로 갈 수 있어.
