챗GPT, 코덱스 개발 복붙 사라지다 - v5.6에서의 혁명적 변화

왕복 노동자에서 총괄 디렉터로

김성현 (byKimjak) 2026 · 07 · 20

그동안 EASTWAR를 만들면서 가장 지치는 순간은 코드를 짜는 시간이 아니었다. 오히려 그 사이를 왔다 갔다 하는 시간이었다.

웹에서 채코치랑 회의하고 설계를 정하면, 채코치가 로컬 코덱스용 지시문을 써준다. 그걸 복사해서 로컬 코덱스에 붙여넣으면 구현과 검증, 커밋까지는 알아서 된다. 문제는 그다음이었다. 그 결과를 다시 복사해서 웹 채코치한테 가져가야 하고, 채코치는 그걸 검토한 다음 다음 지시문을 새로 짜준다. 그럼 나는 또 그걸 복사해서 로컬로 옮긴다. 이 왕복이 하루에도 몇 번씩 반복됐다.

기획자도 아니고 개발자도 아닌, 그냥 텍스트를 나르는 사람이 된 기분이 들 때가 있었다. 그런데 최근 채코치가 이 흐름 자체가 바뀔 수 있다고 말을 꺼냈다.

채코치지금 5.6 Sol Work에서는 이 중간 복붙 과정 대부분을 없앨 수 있어. 김작과 내가 여기서 설계 논의 → 설계 확정 → 내가 GitHub 코드를 직접 읽고 구현 → 테스트·문서 갱신·커밋 → 김작 확인 후 내가 푸시 → 김작 PC에서 git pull → 김작이 실제 Godot F5 화면만 최종 확인. 이렇게 가면 돼.

채코치즉, 로컬 코덱스가 하던 코드 작업까지 이제 여기 있는 내가 직접 할 수 있는 거야.

처음엔 반신반의했다. 그동안 로컬 코덱스가 실행하고, 웹에서 검토하는 구조가 당연하다고 생각했으니까. 근데 곰곰이 생각해보니 그동안 내가 하던 일의 절반은 사실 개발이 아니라 운반이었다. 지시문 복사, 결과 복사, 상태 맞추기. 콘텐츠도 아니고 코드도 아닌, 그냥 사람이 두 시스템 사이의 다리 역할을 하고 있었던 거다.

새 흐름의 핵심은 간단하다. 작업 시작 전엔 로컬 변경을 GitHub에 올려 기준선을 맞추고, 작업 중엔 채코치가 직접 구현·커밋·푸시를 하고, 작업 후엔 내가 로컬에서 pull 받아 F5로 확인만 하면 된다.

로컬 코덱스가 완전히 사라지는 건 아니다. 로컬에만 있는 파일, Godot 실행과 F5 조작, 대용량 영상·이미지처럼 GitHub에 없는 자산 작업은 여전히 로컬의 몫이다. 다만 설계부터 코딩, 검증, 커밋, 푸시까지 한 번에 처리되는 구간이 생겼다는 게 크다.

채코치우리 작업 방식이 이제 진짜 김작 총괄 디렉터 + 채코치 전담 개발팀 구조가 됐네. 이건 EASTWAR 개발 속도 꽤 확 뛸 거야.

총괄 디렉터라는 말이 좀 거창하게 들리긴 했지만, 곱씹어보니 틀린 말은 아니었다. 회의하고, 결정하고, 마지막에 화면 확인하는 것. 그게 원래 내가 해야 했던 일이고, 나머지는 도구가 대신 옮겨줘도 되는 것들이었다.

사용량 확인 같은 건 여전히 로컬 코덱스의 /status, /usage로 따로 봐야 한다는 것도 확인했다. 완전히 하나로 합쳐진 건 아니고, 역할이 재배치된 거에 가깝다. 그래도 하루에 몇 번씩 복붙하며 상태를 맞추던 노동이 줄어드는 것만으로도 체감이 크다.

채코치공식 매뉴얼도 Work mode와 Codex가 동일한 사용량과 한도를 공유한다고 명시하고 있어.

도구가 똑똑해질수록 사람이 해야 할 일은 점점 더 사람만 할 수 있는 일로 좁혀지는 것 같다. 결정하고, 확인하고, 방향을 잡는 일. 그 사이를 메우던 잡일이 줄어드는 건, 결국 창작자로서의 자리를 되찾는 과정이 아닐까.
